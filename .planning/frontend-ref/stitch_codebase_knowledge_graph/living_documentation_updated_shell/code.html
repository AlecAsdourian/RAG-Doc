Data Flow Models

This document details the retrieval and generation data pipelines within the RAG application, outlining how context is fetched, ranked, and injected into the LLM prompt.

info

Context Window Limits

The current model configuration enforces a strict 8k token limit for the context window. Ensure that the chunking strategy in `VectorStoreManager` maintains chunks under 512 tokens to allow for sufficient retrieved context without truncating the prompt.

Retrieval Pipeline

The retrieval pipeline is responsible for fetching relevant code snippets or documentation based on the user's query. It utilizes a hybrid search approach, combining dense vector similarity with sparse keyword matching.

data_object

Dense Retrieval

Uses ADA-002 embeddings to find semantically similar code blocks across the entire indexed repository.

match_word

Sparse Retrieval

BM25 algorithm implemented via Pinecone to ensure exact keyword matches for specific variable or function names.

Implementation Example

Below is the core implementation of the hybrid search query within the `Retriever` class.

def hybrid_search(query: str, top_k: int = 5) -> List[Document]:
    """Executes hybrid search combining dense and sparse vectors."""
    
    # Generate dense embedding
    dense_vec = embedding_model.embed_query(query)
    
    # Generate sparse vector (BM25)
    sparse_vec = bm25_encoder.encode_queries(query)
    
    # Query Pinecone
    results = index.query(
        vector=dense_vec,
        sparse_vector=sparse_vec,
        top_k=top_k,
        include_metadata=True
    )
    
    return parse_results_to_documents(results)
warning

Deprecated Functionality

The `legacy_keyword_search()` method in `search_utils.py` is deprecated as of v1.1.0 and will be removed in v2.0. Migrate all legacy search calls to the new `hybrid_search()` implementation shown above.
