**Who may read it — the user decided on 2026-09-14: any member of the job's organization.**
- It shows their own repository's indexing status.
- Phase 23's progress UI can use it directly.
- **No role gate.** Do not read `OrgRoleKey`.
- **ISS-012 applies here as on every tenant route.** A revoked membership still carries the organization claim, so a removed member could keep reading their former organization's job status. Nothing removes memberships today. Don't solve it here, but name this endpoint in ISS-012's list of affected surfaces.

**Why this endpoint needs care the CI gate won't give it:**
- **No database safety net.** `ingestion_jobs` has no RLS (L5), so nothing in the database stops a cross-tenant read. The handler's `WHERE organization_id = $2` is the only guard.
- **No scanner coverage.** The isolation scanner matches only `POST`/`PUT`/`PATCH`/`DELETE`, and only route lines added in the diff (`check-isolation-tests.py:9-12, 545-561`). A new `GET` passes the gate with no test at all.
- **So the test is written on purpose, and mutation-checked:** removing the organization filter must fail it.
- **⚠ `claim` and `sweep` must never appear in a request handler at all, and today nothing prevents it** — raised by PR #41's review of 21-05, and this is the phase that first puts an HTTP handler over this table. Both statements are queue-wide and cross-tenant BY CONSTRUCTION: no organization filter, no RLS to supply one, and PR #38's review measured an unscoped session claiming another organization's job. `pkg/jobs/doc.go` and `workers/jobs/transitions.py` both say so loudly, but a docstring is not a guard. **Consider making it one while you are in the file** — the cheapest shape is a `grep` gate in the same place the plan already runs one (`claimSQL|sweepSQL` must not appear under `pkg/api/`), which costs a line and catches a paste. Decide and record either way; a stated non-guard that nobody rechecks is what 21-05's review was pointing at.

**Route placement** (fact-checked 2026-09-14):
- The tenant group mounts `/api` with `r.With(middleware.Timeout(60*time.Second)).Route("/api", …)` (`router.go:403`).
- Register **inside** that block as `/admin/jobs/{id}`. A path starting `/api` there would become `/api/api/…`, and registering outside the block loses the 60-second timeout.

**Conventions to follow:**
- **Organization:** comes only from `auth.OrgIDFromContext(ctx)`. A missing one returns 403 (`github_install.go:132-137`).
- **Malformed ids return 404, not 400.** The body is the same as for "not found", on purpose (`repositories.go:235-240`, `github_install.go:443-446`), so a bad id and "not yours" look identical.

**ISS-016 closes only on evidence.** 21-03's and 21-04's racing tests must exist and pass on `main`. ISS-023 (retrying a dead repository through the API) stays open by decision O1.

**Handler `JobsHandler.Get`,** constructed the way `repositoriesHandler` is:

1. **Read the organization** from `auth.OrgIDFromContext`. If it is missing, return 403, as the other tenant handlers do.
2. **Parse `{id}`** as a canonical UUID. Anything malformed gets the **same 404** as not-found.
3. **Query inside `scoper.InTenantTx`,** for consistency with every tenant handler, even though this table has no RLS:
   ```sql
   SELECT id, repository_id, job_type, state, attempts, max_attempts, run_after,
          last_stage, progress, needs_rerun, last_error, ingestion_run_id,
          created_at, updated_at
   FROM ingestion_jobs
   WHERE id = $1 AND organization_id = $2
   ```
   The comment directly above it says that `AND organization_id = $2` is the **only** tenant guard, and why.
4. **One 404 for every miss.** Not-found, another organization's job, and a malformed id all return an identical status and body, so the endpoint is not an existence oracle.
5. **Never return `lease_owner` or `payload`.** `last_error` has already been redacted by the worker (21-05).

**Route:** `r.Get("/admin/jobs/{id}", jobsHandler.Get)` inside the `/api` block. Its comment says the scanner does not cover `GET` routes, and names `jobs_isolation_test.go`.

**`jobs_isolation_test.go`,** using the harness, two orgs and the real middleware:
- **Own job:** org A reads its job → 200, with the expected fields and without `lease_owner` or `payload`.
- **Other org's job:** org B reads org A's job id → 404, **byte-identical** to the 404 for a random UUID.
- **Malformed id:** → the same 404.
- **No tenant in context:** → 403.
- **The full path is `/api/admin/jobs/{id}`:** `/api/api/admin/jobs/{id}` is 404.
- **The mutation check this test exists for:** remove `AND organization_id = $2` from a copy of the handler; the cross-tenant test must fail. Record it.
