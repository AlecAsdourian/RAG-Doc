<objective>
Build the long-running consumer:
- **A worker loop.** It claims a job, checks the installation, then runs a registered handler or defers/abandons the job, and finally completes or fails it.
- **A heartbeat.** It extends the lease and notices a supersede, so the handler can stop (cooperative abort).
- **A periodic sweeper.**
- **Graceful shutdown** and structured logs.
- **A `python -m workers` entrypoint.** It **refuses to start without a registered handler**, so nothing claims and dead-letters real jobs before Phase 22 registers ingestion.

It includes the racing-claim test and the lease-expiry → reclaim → dead-letter test the phase requires.

Output: `workers.jobs.runtime`, `workers/__main__.py`, and integration tests.
</objective>

**There is no worker process today** (fact-checked 2026-09-14):
- `services/workers/Dockerfile` runs `CMD ["python", "-m", "workers"]`, but `workers/__main__.py` does not exist.
- The compose `workers` service builds that image with no command override, and its environment has **no `DATABASE_URL`**, only `ENV=development` (`docker-compose.yml:60-65`).

**Phase 21 must not start processing real jobs.** Once 21-03 and 21-04 ship, connects and pushes enqueue jobs.
- **The risk:** a worker without a real handler would claim those jobs, fail them five times and dead-letter them.
- **The fix, fail closed:** the entrypoint checks for registered handlers **first**, before reading any configuration. With none it logs why and exits 2.
  - Checking first also means the compose service exits 2 with that message, rather than crashing on the missing `DATABASE_URL`.
  - Jobs stay `queued` until Phase 22 registers `full_ingest` and `incremental` handlers and adds `DATABASE_URL` to compose.

**Timings (L3).**
- The lease is 5 minutes, the heartbeat 60 seconds, and the sweeper runs on the heartbeat interval.
- All three are constructor parameters, so tests can use seconds.
- The lease default equals 20-05's `abandonedProcessingAfter = "5 minutes"` (`github_webhook.go:255`); a comment says so.

**Threads.**
- The heartbeat thread gets its own connection.
- psycopg2 connections can be shared between threads, but a shared connection shares its transaction. A heartbeat commit would then commit, or roll back, the handler's work.

**Installation state, checked at claim time** (L2: credentials and installations are read at claim time, not enqueue). After claiming, the worker reads the repository's `installation_id` and that installation's `suspended_at` / `uninstalled_at`, under tenant scope:

| What the worker finds | Action | Why |
|---|---|---|
| `installation_id IS NULL`, or `uninstalled_at` set | `abandon`, then `sync_state = never_synced` | nothing to do; must not retry (`github_webhook_events.go:164-167`) |
| `suspended_at` set | `defer` 60 minutes; no attempt consumed | an unsuspend is noticed within an hour, with no webhook work needed |
| otherwise | `mark_started`, then run the handler | normal path |

**Worker-pool sizing** is an open input in the research doc (RESEARCH, around 200-208), to be measured in Phase 22.
- Each worker process runs **one job at a time**. Scale by running more processes.
- The claim is safe across any number of them (`SKIP LOCKED`).
- The summary records this as the Phase 22 sizing hand-off.

```python
class JobContext:
    job: Job
    def should_abort(self) -> bool            # set by the heartbeat on LeaseLost / superseded
    def report_progress(self, stage: str, progress: dict) -> None  # fenced write of last_stage/progress

Handler = Callable[[JobContext], Callable[[cursor], None] | None]  # may return a write_results callback

class Worker:
    def __init__(self, dsn: str, handlers: dict[str, Handler], *, worker_id: str | None = None,
                 lease=timedelta(minutes=5), heartbeat=timedelta(seconds=60),
                 idle_poll=timedelta(seconds=5), suspended_defer=timedelta(minutes=60)): ...
    def run(self, stop: threading.Event) -> None
```

**`handlers.py`:** `REGISTRY: dict[str, Handler] = {}`. It is empty in Phase 21, and a comment points at Phase 22.

**Construction:** refuse an empty handler map with `ValueError`.

**The loop, until `stop` is set:**
1. **Sweep,** if a heartbeat interval has passed since the last sweep.
2. **Claim.** If nothing comes back, wait `idle_poll`, jittered ±20%, or until `stop`.
3. **No handler for the job type:** `fail` it with `last_error = "no handler for <type>"`. This is defensive; `__main__` prevents it in real deployments.
4. **Installation check,** per the table above: `abandon`, `defer`, or go on.
5. **`mark_started`.**
6. **Start the heartbeat thread,** on its own connection. Every interval it runs a fenced `UPDATE ingestion_jobs SET lease_expires_at = NOW() + lease, updated_at = NOW() WHERE id AND lease_owner AND state = 'running' RETURNING id`. Zero rows (superseded or reclaimed) → set the abort flag and stop heartbeating.
7. **Run the handler:**
   - it returns normally → `complete` with its `write_results`, unless the abort flag is set, in which case log and write nothing
   - it raises → `fail`
   - `LeaseLost` from either → log a warning and carry on
8. **Stop the heartbeat thread** and join it.

**Shutdown.** On `stop`, finish the current job, or return once the handler sees `should_abort`. Never abandon a job mid-write.

**`workers/__main__.py`,** in this order:
1. Import `REGISTRY`. If it is empty, log "no job handlers registered; ingestion handlers arrive in Phase 22 — refusing to start so queued jobs are not dead-lettered" and `sys.exit(2)`.
2. Read `DATABASE_URL`. If it is missing, log that clearly and `sys.exit(2)`.
3. Install SIGTERM and SIGINT handlers that set `stop`, then run.

**Logging:** one structured line per transition and per heartbeat failure, with job id, organization, repository, attempt and worker id. No payloads, no tokens.

**The Phase 22 hand-off,** documented in the module docstring:
- register handlers in `REGISTRY`
- add `DATABASE_URL` to the compose `workers` service
- after that, the entrypoint starts

**Setup:** use the isolation container, with short timings: lease 2 s, heartbeat 0.5 s, idle poll 0.1 s, suspended deferral 1 s. Poll against deadlines; never use fixed sleeps.

**Tests:**
- **End to end:** enqueue a job; a `Worker` runs a test handler that records its call and returns a `write_results` probe. The job ends `completed` and the probe row exists.
- **Heartbeat extends the lease:** a handler that runs for three times the lease still completes, and `lease_expires_at` moved forward while it ran.
- **Supersede mid-run:** the handler loops on `should_abort()` while the test marks the job `superseded` via SQL. The handler aborts within about two heartbeats, nothing is written, and the state stays `superseded`.
- **Lease expiry → reclaim → retry → dead:**
  - **Crash:** worker A's handler blocks, and its heartbeat is disabled via a test hook, simulating a dead process.
  - **Reclaim:** once the lease expires, worker B reclaims and `attempts` goes up.
  - **Exhaustion:** repeat until `max_attempts` (set to 3 for this test); the sweeper then moves the job to `dead`.
  - **Assert:** the final state is `dead`, and no write from a stale worker landed.
- **A claim race that actually races:**
  - **Setup:** 8 threads, each with its own connection, released through a `threading.Barrier` to claim one queued job.
  - **Assert:** exactly one claim succeeds.
  - **Repeat:** 5 rounds on a warm pool. A single cold round proves nothing (21-CONTEXT).
- **Suspended installation:** the handler is never called. The job is deferred with its attempts unchanged; after the suspension is cleared it runs and completes.
- **Uninstalled installation, and `installation_id IS NULL`:** in each case the handler is never called, the job ends `superseded`, and `sync_state = never_synced`.
- **Entrypoint:** run `python -m workers` in a subprocess with no handlers, with and without `DATABASE_URL`. Both runs exit 2 with the handler message.

**Mutation checks,** each on a copy, each confirming a test fails. Record the results.
- remove the heartbeat's fence
- remove the abort check before `complete`
- drop `FOR UPDATE SKIP LOCKED` from the claim → the race test catches the double claim
- replace `defer` with `fail` for suspended installations → the suspended test sees attempts consumed
