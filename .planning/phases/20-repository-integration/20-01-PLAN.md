<objective>
Resolve ISS-008: give Go handlers a request-scoped tenant transaction, so a handler can read and write RLS-scoped tables without either silently returning zero rows or being refused by the 000009 trigger.

Nothing else in Phase 20 can be built first. `GET /api/repositories` is the first Go handler in the project's history to read an RLS-scoped table, and without this it does not work.

Output: a primitive handlers use, wired into the middleware chain, with tests proving both that it scopes correctly AND that a handler bypassing it fails loudly rather than quietly.
</objective>

**Why this is blocking, verified 2026-09-08:**

- `repositories`, `ingestion_runs`, `chunks`, `queries`, `retrievals`, `feedback` have RLS (000008) and the `assert_tenant_scoped` trigger (000009).
- The only Go handler touching the database today is `user_orgs.go`, which reads `users` / `organizations` / `organization_memberships` — none RLS-scoped.
- So the project has never had a Go handler read an RLS-scoped table. Phase 20 is where that changes.

**What already exists to build on:**
- `isolation.TenantScope(ctx, pool, tenantID)` — opens a tx and sets `app.current_tenant`. Test-only today, and the reference implementation for the production version.
- `auth.TenantMiddleware` — has `_ = db` and a TODO reserving exactly this work.
- `auth.OrgIDKey` on the request context, sourced from the verified JWT claim (19-03) and validated as a UUID (19-04).

**Constraining decisions:**

- **`SET LOCAL` requires an explicit transaction and cannot be parameterized.** Both were learned painfully in 17-02, where a naive attempt crashed every request with a 500. The tenant id must be interpolated, which is why 19-04 made `ExtractOrganizationID` return a parsed, canonical UUID — do not weaken that.
- **A handler that forgets to use this must fail loudly.** The 000009 trigger already refuses unscoped writes with SQLSTATE 42501. The dangerous case is an unscoped READ, which RLS answers with zero rows and no error. The design must make that hard to do accidentally.
- **Do not hold a transaction open across an SSE stream.** `/api/chat/stream` is long-lived; a per-request transaction spanning it would pin a pool connection for the life of the stream. Streaming routes must be able to opt out.
</context>

<task type="auto">
  <name>Task 1: Decide and document the design before writing it</name>
  <files>.planning/phases/20-repository-integration/20-01-DESIGN.md</files>
  <action>
ISS-008 records two options. Pick one, write down why, and note what the other would have cost. This is a short document, not a ceremony — but the decision outlives the code and the reasoning is the part that gets lost.

**Option A — middleware opens the transaction.** `TenantMiddleware` begins a tx, sets `app.current_tenant`, stashes it on the request context, commits on 2xx and rolls back otherwise.
- Handlers cannot forget it.
- Every request holds a connection for its full duration, including requests that never touch the database.
- Commit-on-2xx couples transaction semantics to HTTP status, which is subtle and surprising.
- Needs an explicit opt-out for SSE.

**Option B — handlers call a scoped helper.** A production `TenantScope` equivalent; each handler that needs the database opens its own transaction.
- Explicit, no hidden connection lifetime, no HTTP-status coupling.
- A handler can forget, and an unscoped read fails silently.

A third shape worth considering, and the one the author of this plan leans toward: **Option B plus a lint-or-test-level guard.** The 17-05 CI scanner already parses the router for endpoints; a similar check — or a test that asserts every handler touching `pgxpool` goes through the scope helper — converts B's failure mode from silent to caught. That combination gets B's honesty without B's footgun.

Record the choice, then implement it in Task 2.

  <verify>Document exists; the chosen option is stated with its trade-off, and the rejected option's cost is written down rather than implied.</verify>
  <done>A future reader can tell why this shape and not the other.</done>

<task type="auto">
  <name>Task 2: Implement the primitive</name>
  <files>services/backend/pkg/db/tenant.go (new), services/backend/pkg/auth/middleware.go</files>
  <action>
Implement the design from Task 1.

Whatever the shape, these properties are required:

1. **Tenant comes from the verified claim only.** Read `auth.OrgIDKey`, which is populated from the JWT by `TenantMiddleware`. There is no other source. Do not add a parameter that lets a caller pass a tenant id — that is the header vulnerability 19-03 removed, wearing a different hat.
2. **The tenant id is interpolated, so it must be a UUID.** `ExtractOrganizationID` already guarantees a canonical UUID. Re-validate at the interpolation site anyway: this is the one place in the codebase where a string is concatenated into SQL, and it should be defensible in isolation rather than by reference to a caller three layers up.
3. **Rollback on any error path, always.** `defer tx.Rollback(ctx)` after a successful `Begin`; rollback after commit is a no-op.
4. **Explicit opt-out for streaming routes**, or a design where they simply do not use it.

Remove the `_ = db` and the TODO from `TenantMiddleware` — whichever way this lands, that placeholder stops being accurate.

<task type="auto">
  <name>Task 3: Prove it works AND prove bypassing it fails</name>
  <files>services/backend/pkg/db/tenant_isolation_test.go (new)</files>
  <action>
Two halves. The second is the one that matters.

**It scopes correctly.** Using `WithTwoOrgs`: a handler-shaped caller in orgA's scope reads orgA's repositories and not orgB's; writes land under orgA; a write attempting orgB's tenant id is refused.

**Bypassing it fails loudly.** Query an RLS-scoped table through the pool WITHOUT the scope helper and assert the result is unusable — zero rows on read, SQLSTATE 42501 on write. This documents the failure mode in executable form, so the next person who wonders why their handler returns nothing finds a test that says so.

**Mutation-check both**, per the standard established in 19-03/19-04: break the primitive (drop the `SET LOCAL`) and confirm the scoping tests go red. A test that cannot fail is worse than no test, and this suite is the foundation every Phase 20+ handler stands on.

Note for whoever writes this: `SetupTestDB` connects as `rag_doc_app` (NOSUPERUSER NOBYPASSRLS) precisely so RLS applies. If a test unexpectedly sees everything, check which role it is using before concluding RLS is broken.
