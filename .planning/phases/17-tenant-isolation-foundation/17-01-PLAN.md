<objective>
Build the Go integration-test harness that all future tenant-isolation tests use.

Purpose: Every subsequent v1.0 phase adds mutation endpoints. Without a working test harness that spins up a real Postgres, applies migrations, and lets tests operate as two distinct tenants, we cannot prove isolation on any endpoint we ship. This plan makes the harness real and resolves ISS-006 (host-to-container DB connectivity).

Output: A `pkg/testing/isolation` package with `SetupTestDB`, `WithTwoOrgs`, `TenantScope`, and `AssertNoCrossTenantLeak` primitives. All future Go isolation tests use these.

**Constraining decisions (from CONTEXT.md and STATE.md):**
- Test container: testcontainers-go (ephemeral, self-managed, works from Windows host — resolves ISS-006 which was rooted in docker-compose port binding not reaching host)
- Test isolation: shared container reused across the test package, per-test transaction with BEGIN...ROLLBACK for speed; a small subset of tests that need to observe committed state use their own transactions with explicit commit + cleanup
- Naming: package `pkg/testing/isolation`, helper `WithTwoOrgs`, primitive `AssertNoCrossTenantLeak`, tenant scoping via `TenantScope(ctx, pool, tenantID)`

**Issue being addressed:**
- ISS-006: Test database connectivity — resolved by using testcontainers-go instead of relying on docker-compose Postgres

**v2 door-keeping:**
- The harness must not encode assumptions about which tables are tenant-scoped beyond a single registry list. Future graph tables added in v2 register into the same list and inherit fixtures for free.

Add `github.com/testcontainers/testcontainers-go` and `github.com/testcontainers/testcontainers-go/modules/postgres` to go.mod. Create `pkg/testing/isolation/container.go` with `SetupTestDB(t *testing.T) *pgxpool.Pool`:
- Uses testcontainers-go Postgres module with `postgres:16-alpine` image
- Reuses container across test package invocations via `testcontainers.WithReuse(true)` and a stable name (`rag-doc-isolation-tests`)
- Applies all migrations from `services/backend/migrations/*.up.sql` in numeric order via helper in migrator.go (use golang-migrate library programmatically, not the CLI, to keep the harness self-contained)
- Returns a `*pgxpool.Pool` connected to the ephemeral DB
- Registers `t.Cleanup` to close pool; container itself persists between tests for speed

Avoid: relying on the docker-compose Postgres on port 5434. That approach failed as ISS-006. Testcontainers manages its own port mapping.

Avoid: running each test in a fresh container — too slow. One container per test package, transaction rollback per test.

<task type="auto">
  <name>Task 2: Fixture helpers and cross-tenant assertion primitive</name>
  <files>services/backend/pkg/testing/isolation/fixtures.go, services/backend/pkg/testing/isolation/tenants.go, services/backend/pkg/testing/isolation/fixtures_test.go</files>
  <action>
Create `fixtures.go` with `WithTwoOrgs(t *testing.T, pool *pgxpool.Pool, fn func(orgA, orgB *TestOrg))`:
- Creates two orgs with distinct slugs (`iso-test-a-<uuid>` / `iso-test-b-<uuid>`)
- Each org gets an owner user, an admin user, and a member user (all with unique emails, deterministic IDs seeded from test name for debuggability)
- Populates one repository per org (needed for chunk/query tests later)
- `TestOrg` struct exposes `.ID`, `.OwnerJWT`, `.AdminJWT`, `.MemberJWT`, `.RepoID`
- Uses testify or plain t.Cleanup to delete all created rows after the test completes (safety net beyond transaction rollback)

Create `tenants.go` with:
- `TenantScope(ctx context.Context, pool *pgxpool.Pool, tenantID string) (pgx.Tx, error)` — begins transaction, runs `SET LOCAL app.current_tenant = $1`, returns tx (caller commits or rolls back)
- `AssertNoCrossTenantLeak(t *testing.T, pool *pgxpool.Pool, tenantA, tenantB string, action func(tx pgx.Tx) error, observe func(tx pgx.Tx) (bool, error))` — runs `action` as tenantA in a transaction (commits it), then runs `observe` as tenantB in a fresh transaction and asserts it returns false; fails with detailed message showing both tenants and the observation function name

Create `fixtures_test.go` with 4 self-tests:
1. `WithTwoOrgs` creates two orgs with distinct IDs and no overlap
2. `TenantScope(ctx, pool, orgA)` sets `app.current_tenant` correctly
3. `AssertNoCrossTenantLeak` catches an actual leak (test intentionally inserts a row that should be invisible cross-tenant — via `SET ROLE postgres` bypass — and asserts the assertion fails)
4. `AssertNoCrossTenantLeak` passes on a properly isolated action (insert as A, verify B cannot see it)

Avoid: hand-crafting JWTs. Use a `TestJWT(userID, orgID, role)` helper that signs with a test-only key; the auth middleware in Phase 19 will validate real Supabase JWTs, but for isolation tests we only need the middleware to extract claims correctly.

**v2 breadcrumb:** The `WithTwoOrgs` fixture must not hard-code the set of tenant-scoped tables it populates beyond `organizations` and `repositories`. Future tables (chunks-in-graph, memory records) will be populated by test-specific setup inside the closure.
  </action>
  <verify>
`go test ./pkg/testing/isolation/... -run TestFixtures -v` — all 4 self-tests pass. `go vet ./pkg/testing/isolation/...` clean. Fixtures produce valid rows verified by manual `SELECT * FROM organizations WHERE slug LIKE 'iso-test-%'` in a debug run.
  </verify>
  <done>Harness usable by any future test with 3 lines: `pool := isolation.SetupTestDB(t); isolation.WithTwoOrgs(t, pool, func(a, b) { ... })`. Cross-tenant assertion primitive proven both ways (catches real leaks, passes real isolation).</done>
