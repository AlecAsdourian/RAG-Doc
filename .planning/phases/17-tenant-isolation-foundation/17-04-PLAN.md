Add `testcontainers[postgres]` and `pytest-asyncio` to `pyproject.toml` (dev group).

Create `workers/db/tenant.py` with:
```python
from contextlib import asynccontextmanager
import asyncpg

@asynccontextmanager
async def require_tenant(pool: asyncpg.Pool, tenant_id: str):
    """Sets app.current_tenant for the duration of a transaction.
    Every DB access in workers that touches tenant-scoped tables MUST be wrapped in this.
    """
    async with pool.acquire() as conn:
        async with conn.transaction():
            await conn.execute("SET LOCAL app.current_tenant = $1", tenant_id)
            yield conn
```

Create `tests/isolation/conftest.py` with pytest fixtures:
- `test_db_container` (session scope) — spins up Postgres via testcontainers-python, applies migrations from `services/backend/migrations/*.up.sql` in order (share the migrations dir with Go), yields connection info; reused across all tests in the session
- `db_pool` (function scope) — creates asyncpg pool against the container, yields, closes on teardown
- `with_two_orgs` (function scope) — creates two `TestOrg` dataclass instances (id, owner_user_id, admin_user_id, member_user_id, repo_id, jwt_owner, etc.), inserts rows via `require_tenant`; yields orgs

Create `tests/isolation/fixtures.py` with:
- `TestOrg` dataclass mirroring Go's `TestOrg` struct
- `assert_no_cross_tenant_leak(pool, tenant_a, tenant_b, action, observe)` async helper — runs `action` as tenant A, then `observe` as tenant B, asserts observe returns falsy

Create `tests/isolation/test_harness.py` — 4 self-tests mirroring Go's `fixtures_test.go`:
1. `with_two_orgs` creates two orgs with distinct IDs
2. `require_tenant` sets app.current_tenant correctly (query `SELECT current_setting('app.current_tenant', true)` inside the block)
3. `assert_no_cross_tenant_leak` catches a real leak (bypass require_tenant via raw connection, insert cross-tenant, assert helper fails)
4. `assert_no_cross_tenant_leak` passes on genuinely isolated action

Avoid: reimplementing migration logic in Python. Read the SQL files from `services/backend/migrations/` and execute them in order via asyncpg. Single source of truth for schema is Go migrations.

Avoid: using pytest-postgresql. It's more fragile on Windows and requires local Postgres. Testcontainers manages its own Postgres in Docker like Go's harness.

**Sub-step C: Isolation tests.** Create two test files:

`test_postgres_writer_isolation.py`:
1. Writer with correct tenant: `write_chunks(pool, tenant_a, chunks)` under `with_two_orgs` — chunks visible to tenant A, not tenant B (query as B via `require_tenant`)
2. Writer without tenant fails loudly: call the underlying `_insert_chunks` (or refactored equivalent) with a raw connection that has NOT set app.current_tenant — assert asyncpg raises with the trigger's exception message (cross-language proof of 17-03 trigger firing on Python writes)
3. Cross-tenant write attempt: write as tenant A with tenant_id=B's ID in the payload but session set to A — expect either RLS refusal or trigger raise (verify one of them fires; if it silently succeeds that's a bug)

`test_query_engine_isolation.py`:
1. Query as tenant A returns only A's chunks
2. Query as tenant B (identical query text) returns only B's chunks
3. Query with no tenant set returns empty (RLS silent-filter) — verify the query engine detects empty-with-no-tenant and logs a warning (defensive UX; the trigger won't fire on SELECT)

Fix any leaks discovered as part of this plan. Do not defer.
