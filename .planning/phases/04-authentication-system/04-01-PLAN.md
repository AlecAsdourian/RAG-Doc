- Database primary keys: UUIDs (distributed-systems ready)
- Timestamp type: TIMESTAMPTZ (always store timezone)
- Delete behavior: CASCADE for multi-tenant hierarchy
- Migration tool: golang-migrate

**From RESEARCH.md:**
- **Don't hand-roll:** Multi-tenant database queries (use PostgreSQL RLS instead)
- **Defense in depth:** Application middleware + PostgreSQL RLS (both layers)
- **RLS best practices:**
  - Keep policies simple (check current row only, avoid sub-SELECTs)
  - Use FORCE ROW LEVEL SECURITY (apply to table owner too)
  - Set LOCAL app.current_tenant per request (not per connection)
  - Create indexes on tenant columns (organization_id)

**From CONTEXT.md:**

- Two roles for now: admins can invite users and manage org, members can access data
- Database row-level security (RLS) as safety net

<task type="auto">
  <name>Task 2: Enable RLS and create policies for multi-tenant tables</name>
  <files>services/backend/migrations/000007_enable_rls_policies.up.sql, services/backend/migrations/000007_enable_rls_policies.down.sql</files>
  <action>
    Create migration 000007 that enables RLS on all tenant-scoped tables and creates isolation policies.

    **Enable RLS on existing tables:**
    - ALTER TABLE repositories ENABLE ROW LEVEL SECURITY;
    - ALTER TABLE chunks ENABLE ROW LEVEL SECURITY;
    - ALTER TABLE ingestion_runs ENABLE ROW LEVEL SECURITY;
    - ALTER TABLE queries ENABLE ROW LEVEL SECURITY;
    - ALTER TABLE retrievals ENABLE ROW LEVEL SECURITY;
    - ALTER TABLE feedback ENABLE ROW LEVEL SECURITY;

    **Force RLS (CRITICAL - apply to table owner too):**
    - ALTER TABLE repositories FORCE ROW LEVEL SECURITY;
    - (repeat for all tables above)

    **Create simple, performant policies (from RESEARCH.md best practices):**

    For repositories:
    CREATE POLICY tenant_isolation ON repositories
      FOR ALL
      USING (
        EXISTS (
          SELECT 1 FROM projects
          WHERE projects.id = repositories.project_id
          AND projects.organization_id = current_setting('app.current_tenant', true)::uuid
        )
      );

    For chunks (references repositories):
    CREATE POLICY tenant_isolation ON chunks
      FOR ALL
      USING (
        EXISTS (
          SELECT 1 FROM repositories r
          JOIN projects p ON r.project_id = p.id
          WHERE r.id = chunks.repository_id
          AND p.organization_id = current_setting('app.current_tenant', true)::uuid
        )
      );

    Repeat pattern for other tables (ingestion_runs, queries, retrievals, feedback) - all trace back to organization through their foreign keys.

    **Why this pattern:** Check current row only (no sub-SELECTs in policy expression itself - uses EXISTS instead). The EXISTS subquery is evaluated once per policy check, more efficient than correlated sub-SELECT. From PostgreSQL RLS documentation best practices.

    **Down migration:** DROP POLICY for all policies, DISABLE ROW LEVEL SECURITY on all tables.
  </action>
  <verify>Migration files created, policies reference correct columns and relationships</verify>
  <done>RLS enabled on all tenant tables with FORCE, policies created using EXISTS pattern (not correlated sub-SELECTs), down migration drops policies and disables RLS</done>
