**Two open questions from `22.2-CONTEXT.md` this plan settles:**
- **The chunk-set digest.** SHA-256 over the sorted multiset of rows
  `(file_path, start_line, end_line, chunk_type, sha256(content),
  sha256(breadcrumb), sha256(docstring))`.
  - It is taken over the corpus's rows **with the run's embedding model**.
  - CONTEXT's draft hashed the content alone. But the embedded text is
    breadcrumb, then docstring, then content
    (`embedding_generator.py:67-103`), so two arms with equal content and
    different docstrings would have passed as identical.
  - With these fields, equal digests mean identical embedded text under the
    same generator.
- **The chunker version.** The first 16 hex characters of a SHA-256 over two
  things:
  - the relative path and bytes of every non-test `.py` file under
    `workers/parser/` and `workers/chunker/`;
  - the installed versions of `tree-sitter` and each grammar package.

  It names the code. The digest names what is stored.
  - 22.2-04, which makes either chunker ingestible, extends the version with
    the variant it selects.

**Lessons that apply here** (review checklist):
- **A helper carrying its own copy of a predicate is blind to changes.**
  - The census imports the harness's file selection.
  - Its embedded-text copy is pinned to the generator by a test until
    22.2-02 replaces it.
  - The harness, `compare_runs.py`, the tripwire and (in 22.2-07) the judge
    all call `scoring.aggregate`.
- **The mutation rule, the same in all four 22.2 plans:**
  1. commit the code and its tests first;
  2. apply each mutation in the worktree, to the real file, neutered rather
     than deleted (never on a copy: a test that imports the original never
     sees a copy);
  3. prove it landed by reading bytes: the file's bytes differ from `HEAD`'s;
  4. run the tests and record which one fails;
  5. restore with `git checkout -- <file>`, and prove the restore by bytes
     equal to `HEAD`'s.

  Text mode is not a proof: in 22-05 it translated CRLF and made a proof that
  could not fail. The table of mutations, failing tests and byte checks goes
  in the plan's records.
- **Measure before claiming.** Each result is the tool's own output, recorded
  verbatim with its command.
- **Reproduce from a clean export** (`git archive`), never from the working
  tree. Untracked or ignored files let a reproduction pass that a clean
  checkout would fail.
- **Evidence is never kept out of a commit.**
  - The root `.gitignore` ignores `*.log`, `logs/` and `=*`.
  - `services/workers/.gitignore` ignores `lib/`, `build/`, `dist/`, `var/`
    and `env/`.
  - Records go to `22.2-01-records/` as `.txt`, `.json` or `.gz`, and
    `git check-ignore` on each finds none.
- **Environment facts:**
  - never compose's Postgres, and never port 5434, which another project
    binds;
  - every harness call passes `--corpora-dir`;
  - the workers venv runs the tests;
  - never print `OPENAI_API_KEY`: check it by its length.
