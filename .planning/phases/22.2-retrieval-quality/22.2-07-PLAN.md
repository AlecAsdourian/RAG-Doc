**The rule schema,** validated on load. A rule that fails it means exit 2.
- `rule`: the id, such as `"M2"` or `"chunk-shape"`.
- `protocol`: the `.md` file beside it.
- `set`, `corpora`, `top_k` (5) and `metric` (`"mrr@5"`).
- `variable`: `embedding_model` or `chunker`.
- `arms`: each arm's record prefix, and the variable's declared value on it.
  `decide.py` checks each record's header against the declaration: the model,
  or the chunker version and variant.
- `after` (optional): the id of a rule that must be applied first. Its verdict
  chooses this rule's arms (`arms_by_verdict`: `ADOPT` and `REJECT`, each
  naming a baseline arm and a candidate arm).
- `clauses`: a list of `{id, level: file|symbol, scope: pooled|each_corpus,
  min_delta}`. A clause holds when Δ ≥ `min_delta` − `allowance`.
- `allowance`: 1e-9.

**`embedding-model-rule.json`: M2, exactly.**
- The clauses:
  1. symbol, pooled, 0.03;
  2. file, pooled, 0;
  3. file, each corpus, −0.11.
- `set: "shape-model"`; corpora miniflux, mealie and linkwarden;
  `variable: "embedding_model"`; baseline `text-embedding-ada-002`, candidate
  `text-embedding-3-small`.
- `after: "chunk-shape"`. The arms follow the verdict:
  - `ADOPT`: `candidate-ada` against `candidate-3small`;
  - `REJECT`: `current-ada` against `current-3small`.

**`decide.py`** takes `--rules R1.json [R2.json]`, applied in the order given
(a rule with `after` must come after the rule it names); `--records DIR`
(`<arm>-<corpus>.jsonl`, `.gz` accepted); `--specs DIR`; and
`--query-vectors MODEL=FILE …`.

**It refuses, with exit 2, before comparing anything, when:**
1. the question sets differ, by id or by text, across the arms or against the
   spec's set;
2. a record's ranks are not what its own final list gives under
   `scoring.ranks`;
3. a measuring connection (either leg, or the header's) is a superuser,
   bypasses RLS, or is unrecorded;
4. any query failed;
5. two compared arms differ in anything except their declared variable:
   - `corpus`, `commit`, `set`, `top_k`, `boost_config`, `exact_paths`,
     `harness_commit` and `vector_backend` must match;
   - for a model comparison, the `chunk_set_digest` must match;
   - for a chunk comparison, the model must;
6. a question's cached vector, in its run's model's file, has another model,
   or a hash other than the record's `query_vector_sha256`;
7. **a rule file was committed after its questions:**
   - the commit that added the rule's JSON must be a strict ancestor of the
     commit that added the set's first question, in every corpus spec;
   - it refuses if either is uncommitted, or if one commit adds both, since
     the order cannot then be proven;
8. a rule fails the schema, or `after` names a rule not applied first.

**It prints:**
- per corpus and pooled, for each pair judged: MRR, recall and rank-1 at 5,
  for file and symbol;
- MRR@20, reported;
- the per-question table of ranks, per arm;
- the questions whose rank sits in a tie at the cut, at QD2's 2e-6, reported

- each clause evaluated, with its value, its threshold, and whether it holds;
- `VERDICT: ADOPT` or `REJECT` per rule.

**The exit code:** 0 when every rule it ran adopted, 1 when any rejected, 2

**Independence, in `validate_spec`:**
- A question in a decision set may not target a `(path, symbol)` that any
  other question of the corpus targets, in any set. Two targets are the same
  when the paths are equal and either symbol matches the other under
  `scoring.symbol_matches` (so `Class.method` and `method` in one file are

    targets a symbol any existing question targets", read as a bare name. It
    is the right reading here: scoring identifies an answer by path and
    breadcrumb (`scoring.py:24-56`), and a bare-name rule would refuse
    unrelated questions, since names repeat across files (a Next.js
    codebase has a `handler` in nearly every API route). A question on the
    same name in another file is a different answer to score.
