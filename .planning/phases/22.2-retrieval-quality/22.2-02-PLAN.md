**Lessons that apply here** (review checklist):
- **A chunker that fails must never empty or gut an index** (PR #58, review
  B's M3).
  - `_parse` skips raising files and `_write_results` replaces the whole set.
  - **The guard that landed** (`handler.py:314-319`) raises `ParseFailed` when
    `files and parsed == 0`: every file raised. Its test is
    `test_a_chunker_that_fails_on_every_file_fails_the_job_instead_of_emptying_the_index`
    (`tests/ingest/test_handler.py:306`).
  - **Two edges it lets through,** found by the fact-check re-reading it:
    1. some files raise and the rest parse to **zero chunks**: `parsed > 0`,
       so the index is replaced with nothing;
    2. one trivial file parses while every real file raises: the index
       shrinks to that file's chunks.

    Neither can happen with today's chunker: it never raises today (every
    fallback in every corpus is "no chunk"), and a non-empty file always
    yields at least one window. 22.2-02 changes the chunker, so Task 3
    tightens the guard first. The policy chosen is in Task 3.

  matches nothing raises nothing; the file silently falls back to windows.

**TypeScript:**
- **Grammars.** One parser method chooses the grammar from the path and the
  language:
  - `language_typescript()` for `.ts`;
  - `language_tsx()` for `.tsx`;
  - the JavaScript grammar for `javascript`.

  `parse_file` takes the path and uses it, and so does `chunk_file`. The
  census's one "as chunked" call goes through the same method (the one line
  in `chunk_census.py`).
- **Queries are per grammar, not per language.** The parser holds one set of
  compiled query objects per grammar: TS, TSX and JavaScript (and Python and
  Go as today). `extract_functions` and `extract_classes` take the query set
  through **the same selection** that chose the grammar, so a tree is never
  queried with another grammar's objects. A query compiled for one TypeScript
  grammar matches nothing on the other's tree, silently (measured, above).
  - A guard, not only a convention: the parser keeps the grammar a tree was
    parsed with beside it, and querying with another grammar's set raises.
- **Queries.** TypeScript and TSX get rewritten queries; JavaScript gets its
  own.
  - `function_declaration` and `generator_function_declaration`;
  - `class_declaration` and `abstract_class_declaration`, named by
    `type_identifier` in TypeScript and `identifier` in JavaScript;
  - `method_definition` **only inside `class_body`**. Object-literal methods
    are not chunked;
  - a module-level `lexical_declaration` (under `program` or
    `export_statement`) whose declarator's value is an `arrow_function` or
    `function_expression`. That gives one chunk per such declarator, named by
    the variable and spanning the declaration.
  - Not chunked:
    - `export default function () {}`;
    - a function passed to a call (`export const x = wrap(async () => …)`);
    - class-field arrow functions;
    - interfaces, type aliases and enums.
- **Names.** `abstract_class_declaration` becomes a scope and a named node in
  `metadata_builder.py`, so its methods read `Class.method`. A `const`-bound
  function takes the variable's name.
- **Leave JSDoc and decorators to Task 2,** so each task's census isolates its
  own change.
