## Objective

Make the retrieval that Phase 23 puts in front of users the retrieval we mean
to launch with. That takes three steps:
- **Fix what the chunker gets wrong,** with offline proof that it is fixed.
- **Decide three quality questions on fresh blind questions,** each under a
  rule the user commits first:
  - what a chunk should contain;
  - which embedding model;
  - how the keyword leg should search.
- **Add a TypeScript corpus,** so that every decision is also measured on the
  language most customer repositories are written in.

This is U10's track, and DESIGN.md §9 calls it "the real gate". The research
changed what goes inside each step. It keeps the order U10 locked: chunker,
then model, then ranking.

### QD1 — Correctness or quality · LOCKED 2026-09-29, QU2

**A correctness fix** meets three conditions:
- it makes the code do what it states, or what every other language path
  already does;
- it chooses between no designs that would rank differently;
- "fixed" is checkable offline: a census number, a parse, a unit test.

It is adopted on that evidence. The benchmark is re-run on the existing
question sets and **reported, not judged**. This repository's precedent is PR
#27 (Go methods and doc comments), PR #28 (breadcrumbs) and 22-02 (duplicate
vectors).

**The tripwire (QU2's B):** if any benchmark number falls after a correctness
fix, the plan stops and finds out why before merging.
- The SUMMARY names the questions that moved, and why.
- The fix is adopted unless the investigation shows it is wrong.
- Nothing is tuned.

**A quality decision** is one where any of three things holds:
- several reasonable designs exist;
- it removes or re-weights text retrieval can use today;
- its value shows only in ranking.

It is adopted only past a rule committed before its questions exist.

**The classification, confirmed with QU2.** Item by item it is
`22.2-RESEARCH.md` R1's table.
- **Correctness:**
  - the TypeScript grammar and queries;
  - named function expressions;
  - JSDoc;
  - decorators inside their chunk;
  - grouped Go structs;
  - visible truncation.
- **Quality:**
  - class chunks that repeat their methods (ISS-026) and the other duplicates;
  - splitting large functions;
  - chunking types and constants;
  - the model;
  - the keyword leg (ISS-029, ISS-028, ISS-038).
- **Correctness, neutral at today's boosts:** ISS-025's defect 3; and ISS-024,
  whose boosts are deleted (QD9).

### QD2 — The tolerance · LOCKED 2026-09-29, QU10

**The value:** 2.0e-6 on vector similarity, absolute, **fixed 2026-09-29**,
before any track measurement or rule existed.
- **Where it comes from:** 22-03's largest cross-store difference was 6.03e-07
  over 6,395 pairs. 2e-6 is about 3.3× that.
- **Where it applies:** every comparison in this phase of two runs' scores for
  the same stored vectors. That covers two things:
  - the equivalence runs that prove a change neutral (QD9's cleanups, and
    22.1-01 if it claims no ranking change);
  - ties at a rank cut in a decision's report.
- **Where it does not apply:** across two separate ingests. Whether the
  embedding API returns identical vectors for identical text is not verified.
  22.2-01 measures it, for about $0.001, before any rule relies on it.
- **The tool:** `compare_runs.py` gains a `--vector-tolerance` flag defaulting
  to 22-03's 1e-5, so the committed 22-03 verdict re-judges byte-identically.
  This phase passes 2e-6. The harness's exact-list tie tail
  (`EXACT_TIE_TOLERANCE`) follows the same flag.

### QD3 — The judge · PROPOSED (the user, at the approval of PR #59's plans)

`compare_runs.py` cannot judge this phase's decisions. It refuses runs whose
models or query-vector hashes differ, and it needs a Qdrant point set that can
never be recorded again (R4). **`decide.py`** is built in 22.2-07.

*2026-09-29, PR #59:* `decide.py` was 22.2-01's. It moved to 22.2-07 when
22.2-01 was split at the task limit (see "The plans").
- `22.2-07-PLAN.md` carries this decision as written, with its alternative
  (verdicts computed by hand, as PR #32 did) and what changes if that is
  picked.
- The user decides it when approving that PR's plans.

**Its input:**
- the recorded runs per corpus for a decision's question set: **two arms, or
  four for the shared chunk-shape and model set** (QD8);
- each rule, as a small JSON file committed beside its protocol document, and
  proven to encode the document's text. So the judge cannot be changed after
  the numbers exist without a visible commit.

**It applies the rules in order.** For the shared set:
1. the chunk-shape rule on the two ada-002 arms;
2. then M2 on the two arms whose chunker that verdict adopts.

**It refuses** (exit 2), before comparing anything, when:
- the question sets differ, by id or by text;
- a record's ranks are not what its own final list gives under `scoring.py`;
- a measuring connection is a superuser, bypasses RLS, or is unrecorded;
- any query failed;
- two arms being compared differ in anything except their declared variable.
  For a model comparison that means the chunk-set digests must match; for a
  chunk comparison, the models must;
- a query vector was embedded with a model other than its run's;
- a rule file was committed after its questions (read from `git log`).

**It prints:**
- per corpus and pooled: MRR, recall and rank-1 at 5 for file and symbol, plus
  MRR at 20, reported;
- the per-question table;
- each clause of each rule, evaluated;
- `VERDICT: ADOPT` or `REJECT` per rule. The exit code covers the rules run.

Every refusal has a test, and every guard a killed mutation, as
`compare_runs.py` has.

### QD5 — The TypeScript fix · LOCKED 2026-09-29, QU2

The design constraints for 22.2-02:
- **Grammars:**
  - `tree_sitter_typescript.language_typescript()` for `.ts`;
  - `language_tsx()` for `.tsx`;
  - JavaScript keeps its own grammar *and gains its own queries*.

  Today JavaScript shares the TypeScript queries
  (`tree_sitter_parser.py:110`). The TS class query must name a
  `type_identifier`, which the JavaScript grammar does not have. Today's
  class query fails to compile under both TypeScript grammars
  (`22.2-records/ts-grammar-checks.txt`).

  `.tsx` needs to be told apart where the language is decided: a `tsx` key in
  `workers/fetch/filters.py`'s `LANGUAGES` and in the harness, or a parser
  choosing by extension. The plan picks one.
- **What gets chunked,** for parity with Python and Go:
  - function declarations and methods;
  - classes, abstract classes included;
  - module-level `const`/`let` bound to an arrow function or a function
    expression, exported or not, named by the variable.

  Anonymous callbacks are not chunked, as Python lambdas are not.
- **JSDoc:** a `/** … */` block directly above becomes `metadata["docstring"]`,
  as a Go doc comment does.
- **Interfaces, type aliases and enums:** symbols (22.1-01), **not** chunks.
  That is the same rule P8 gives Go's non-struct types. Chunking them is a
  quality bet (QD7).
- **The evidence it is fixed:**
  - the census shows 0 files with parse errors on linkwarden and the self
    frontend;
  - the named chunks match the named declarations (601 on linkwarden);
  - every chunked declaration with a JSDoc block directly above carries it.
    Today's census count of 17 on linkwarden also includes non-function
    constants, so it is an upper bound;
  - fixture tests assert `has_error` is false for TS, TSX and JS fixtures.
    Today's tests do not, which is how the bug hid (R1).

### QD6 — One span rule · LOCKED 2026-09-29, QU2 and QU4 (the chunk side)

**The rule:** a chunk starts at its definition's first decorator.
- It holds for Python, and for TypeScript where tree-sitter-typescript places
  the decorator (22.2-02 checks which).
- **Doc comments** reach the embedded text through `metadata["docstring"]`, as
  today. They are **not** copied into the chunk text as well, which would
  embed them twice.
- **Decided once,** at 22.2-02's approval, the first of the two plans to be
  approved (QU4). 22.1-01 cites it.

**P8's symbol side stays PROPOSED.** The user decides it at 22.1-01's approval.
- Its span, and therefore `span_digest`, must start at the same first
  decorator.
- It includes the leading doc comment, as P8 proposes, so `span_digest` sees a
  comment change.

**Why it matters:** in mealie, 245 of 270 route decorators reach the index
only through the duplicated class chunks (R6). If ISS-026 were adopted before
this rule, they would leave the index altogether. So the rule is a
precondition of QD7, not only an identity detail.

### QD10 — Blind questions · LOCKED 2026-09-29, QU6

**Sets:**
- **15 fresh questions per app,** on miniflux, mealie and linkwarden.
- **The chunk-shape and model decisions share one set** of 45 (QU6's C). It is
  written only after **both** of their rules are committed: M2 (committed
  2026-09-29, and complete since the user confirmed its numbers the same day,
  `afa50b2`) and the chunk-shape rule (22.2-04).
- **The keyword leg gets its own set** of 45 (22.2-06).
- **The TypeScript corpus's base set is 30 questions** (15 tuning, 15 holdout;
  22.2-03).
- That is **120 fresh questions in all.**

**The process** follows PR #31 and the boost protocol:
1. **The rules are committed first:** the protocol file, with the candidate,
   the test set's definition, the rule and its JSON, and the measurement.
2. **The writers.** After that commit, one or two writer agents per corpus are
   launched.
   - Each may read only the pinned checkout: no RAG-Doc code, no harness, no
     database, no web, no retrieval result, and no earlier question files.
   - They get the list of symbols already targeted, to avoid them.
3. **The questions.** Each carries an id, the set name, the question, the
   path, the answering symbol and `path:line` evidence.
   - Phrasing: the way a newcomer asks, never naming the symbol or the file.
     About a third deliberately use words the code does not.
   - Spread: at most five per package.
   - Kinds: a mix of "where", "how", "what happens when" and "what decides".
4. **Committed before any measurement.** That commit order is the evidence.
   Then `--check` runs offline with 0 failures.
5. **A spot-check.** The planner hand-checks at least a third of the answers
   against the cited code, with no retrieval, and records the result.
6. **The measurement.** Each arm is run once, as `rag_doc_app`, recorded
   (gzipped) and judged by `decide.py`. Each verdict is reported whichever way
   it falls.
7. **After the verdicts,** the set is spent for those decisions and becomes
   exploration material for later ones.

The harness gains the new set names (today it accepts only `tuning`,
`holdout` and `confirm`, `rag_quality_harness.py:189`, `:366-367`) in
22.2-07, since the split (PR #59): `shape-model` for the shared set and
`keyword-leg` for 22.2-06's.
