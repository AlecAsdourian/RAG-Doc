`22.2-CONTEXT.md` is the authority for decisions. This file is the authority
for **what "done" means**. M2's two numbers, T = 0.11 and clause 1's +0.03,
were confirmed by the user on 2026-09-29 (`afa50b2`) and are LOCKED in QA10.

**How it is used** (as in `22-ACCEPTANCE.md`):
- **A PR body** has a section "Acceptance criteria" listing the IDs it
  advances, each with its evidence.
- **A review verdict** has a "Criteria check" line per cited ID: holds, does
  not hold, or not verifiable, with what was run.
- **The phase closes** when every criterion is met with evidence recorded in a
  SUMMARY, not when the last plan merges.
- **A criterion that turns out wrong** is corrected here with a dated note,
  never met by a weaker reading.

**A verdict is not a criterion.** Whether a candidate is adopted or rejected is
the protocol's outcome, and either outcome meets these criteria. What they
require is that each decision was made the way its committed rule says.

*Evidence:* one test per refusal and per verdict; a mutation table with every

**QA10 — The embedding-model decision applies its committed rule.** The
default becomes `text-embedding-3-small` only if all three clauses hold,
exactly as committed on 2026-09-29. Otherwise it stays

1. Over all 45 questions of the shared set, symbol MRR@5 with 3-small exceeds
   ada-002's by at least **0.03**.
2. Over all 45, file MRR@5 with 3-small is not lower than ada-002's.
3. On each app's 15 questions, file MRR@5 with 3-small is not lower than

**Both numbers are LOCKED, 2026-09-29.** The user confirmed them before any
question of the shared set existed (`afa50b2`, the protocol's "The user's
confirmation").

- **Clause 1's bar is +0.03,** chosen from +0.03 and +0.06. It was kept

The rule's precision (MRR@5, pooling, the 1e-9 rounding allowance, invalid
runs) is the protocol's. **Neither number can change.** A different bar would
need a new rule and a new set of questions.

*Evidence:* the protocol's commit history; `decide.py`'s printed evaluation of
