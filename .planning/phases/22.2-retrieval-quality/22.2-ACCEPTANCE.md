# Phase 22.2 (proposed name): Retrieval Quality — Acceptance criteria (DRAFT)

Written 2026-09-29, with `22.2-CONTEXT.md` and `22.2-RESEARCH.md`. **A draft.**
It becomes the authority for what "done" means once the user answers
QU1–QU10. Criteria that depend on an answer say which one.

**How it is used** (as in `22-ACCEPTANCE.md`):
- **A PR body** has a section "Acceptance criteria" listing the IDs it
  advances, each with its evidence.
- **A review verdict** has a "Criteria check" line per cited ID: holds, does
  not hold, or not verifiable, with what was run.
- **The track closes** when every criterion is met with evidence recorded in a
  SUMMARY, not when the last plan merges.
- **A criterion that turns out wrong** is corrected here with a dated note,
  never met by a weaker reading.

**A verdict is not a criterion.** Whether a candidate is adopted or rejected is
the protocol's outcome, and either outcome meets these criteria. What they
require is that the decision was made the way the protocol says.

## Criteria

**QA1 — The rules come first.** For each of the three quality decisions
(chunk shape, embedding model, keyword leg):
- The protocol document and its machine-readable rule are committed before any
  of that decision's deciding questions exist. The protocol document states
  the candidate, the test set, the rule and the measurement.
- The questions are committed before any measurement touches them.
- The track's vector-score tolerance (QD2) is dated before the first rule.

*Evidence:* each protocol document's "order of record" table of commits and
times, as `boost-defaults-protocol.md` has, checked against `git log`; and
`decide.py` refusing a rule committed after its questions (tested).
*Advanced by 22.2-04, 22.2-05 and 22.2-06; the refusal by 22.2-01.*

**QA2 — The baseline is reproducible.**
- The committed chunk census tool reproduces every number in
  `22.2-records/census-*.json`, on the pinned corpora at the recorded commits.
- Every later plan that changes the chunker commits its census before and
  after.

*Evidence:* a field-by-field comparison, committed with 22.2-01, which shows
no difference; and the census files of 22.2-02 and 22.2-04. *Advanced by
22.2-01.*

**QA3 — The judge is trustworthy.** `decide.py` refuses, with exit 2 and no
verdict, in each of these cases:
- question sets that differ by id or text;
- a record whose ranks are not what its own final list gives under
  `scoring.py`;
- a measuring connection that is a superuser, bypasses RLS, or is unrecorded;
- a failed query;
- headers that differ in anything except the decision's declared variable;
- for a model decision, arms whose chunk-set digests differ;
- a query vector embedded with another model than its run's;
- a rule committed after its questions.

It prints each clause of the rule evaluated and exits 0 (adopt) or 1
(reject).

*Evidence:* one test per refusal and per verdict; a mutation table with every
guard killed. *Advanced by 22.2-01.*

**QA4 — TypeScript parses, and its functions become chunks.**
- On linkwarden and on this repository's frontend, 0 files parse with errors
  in the grammar the chunker uses (from 351 of 379 and 39 of 43).
- Every named function, including module-level function expressions, every
  method and every class gets a chunk, named as the harness scores it.
  - The count matches the census's parity count: 601 on linkwarden at the
    pinned commit.
  - Or any difference is explained, declaration kind by declaration kind, in
    the SUMMARY.
  - 0 of linkwarden's 213 module-level const functions remain in no chunk
    (from 67).
- JSDoc reaches `docstring`: 17 on linkwarden, from 0.
- `.tsx` is parsed with the TSX grammar. JavaScript files keep the JavaScript
  grammar and have their own queries.

*Evidence:* the census after 22.2-02; fixture tests asserting a clean parse
(`has_error` false) for TS, TSX and JS; `--check` on every corpus. *Advanced
by 22.2-02.*

**QA5 — Decorators are inside their definition's chunk,** under one span rule
shared with 22.1-01 (QD6).
- In mealie: decorators in no chunk go to 0 (from 105).
- Decorators only inside a class chunk go to 0 (from 466).
- The route decorators likewise (from 25 and 245).
- No doc comment is embedded twice.

*Evidence:* the census; a unit test on a decorated method and one on a
decorated top-level function; the span rule cited by 22.1-01's plan.
*Advanced by 22.2-02.*

**QA6 — Nothing is lost silently.**
- A chunk whose embedded text exceeds the token limit is counted and reported,
  in the log and in the job's `progress`.
- Each struct in a grouped Go `type ( … )` gets a chunk of its own spec only.

*Evidence:* unit tests for both; the census's truncation count. *Advanced by
22.2-02.*

**QA7 — Correctness fixes are measured, not judged** (QD1; the tripwire if QU2
is B).
- The benchmark is re-run on the existing question sets after 22.2-02, and
  every aggregate is reported before and after.
- If any aggregate fell and QU2 chose the tripwire, the SUMMARY names the
  questions that moved and why, before merge.

*Evidence:* 22.2-02's SUMMARY. *Advanced by 22.2-02.*

**QA8 — The TypeScript corpus exists.**
- linkwarden, pinned at the approved commit and scoped as QD4.
- 30 blind questions (15 tuning, 15 holdout, the split fixed first), written
  by agents with no retrieval, database or web access, and committed before
  the corpus is first ingested.
- `--check`: 0 failures, every warning reviewed.
- A baseline measured as `rag_doc_app` and committed as records.

*Evidence:* the spec, the commit order, the `--check` output, the records.
*Advanced by 22.2-03.*

**QA9 — Each decision is measured on what ships.**
- The chunk-shape verdict comes before the model decision's measurement,
  which comes before the keyword leg's.
- Every record header names the chunker version, the chunk-set digest and the
  embedding model.
- Each decision's baseline arm is the previous decision's outcome.

*Evidence:* the headers; the protocol documents. *Advanced by 22.2-04, 22.2-05
and 22.2-06.*

**QA10 — Every verdict is recorded, whichever way it falls.** Each protocol
document's Result section holds:
- the aggregates per corpus and pooled;
- `decide.py`'s output and exit code;
- "adopted" or "not adopted".

Beyond that:
- A candidate that fails its rule is not merged as a default.
- Trying it again needs a new rule and new questions.

*Evidence:* the three protocol documents and the gzipped records beside them.
*Advanced by 22.2-04, 22.2-05 and 22.2-06.*

**QA11 — Neutral means neutral.** Every change claimed not to move ranking
passes an equivalence run with 0 questions differing, at QD2's tolerance:
- ISS-024's cleanup;
- ISS-025's defect 3;
- anything else so claimed.

The run uses one scratch database, the same stored vectors and one set of
cached query vectors.

*Evidence:* the equivalence output. *Advanced by 22.2-06* (and by 22.1-01 if it
claims no ranking change).

**QA12 — If the embedding model changes, it changes everywhere.** *(Only if
22.2-05 adopts a new model.)*
- One setting governs the pipeline, the query engine and the answer
  generator's cache lookup, and a test pins that the three agree.
- Every indexed repository is re-embedded.
- ISS-021's entry records that the repaired cache must key on the model and
  re-derive its 0.95 threshold.

*Evidence:* the test; the re-ingest record; the ISSUES.md entry. *Advanced by
22.2-05.*

**QA13 — Measured safely, and costs stated.**
- Every measurement runs on a scratch database, never compose's Postgres and
  never port 5434, and its containers are removed afterwards.
- Each plan states its OpenAI budget up front and its spend in its SUMMARY.
- Every SUMMARY separates what was measured from what was inferred.

*Evidence:* the SUMMARYs; the reviewer's criteria checks.

**QA14 — The track ends with a statement of where retrieval stands.** It
records:
- the final census of every corpus;
- the shipped configuration measured on every question set of every corpus,
  reported, not judged.

Phase 23 cites this record.

*Evidence:* the closing record in 22.2-06's SUMMARY. *Advanced by 22.2-06.*

## Not acceptance criteria

These are out of scope, per `22.2-CONTEXT.md` Boundaries:
- repairing the semantic cache (ISS-021);
- HNSW recall at production scale (22.1-05's);
- moving fusion into SQL (P6);
- SCIP tier 2;
- content-level secret scanning (unless QU9 moves it in);
- chunking documentation files;
- scoring by symbol id;
- an absolute quality bar for launch.

A PR that advances one of these is scope creep unless the user has moved it in.
