## 1. The rule schema, and M2 as JSON

`decide.py` checks every rule on load (`schema_problems`); any failure is refusal 8.

| key | meaning |
|---|---|
| `rule` | the id (`"M2"`, `"chunk-shape"`) |
| `protocol` | the `.md` beside the JSON; it must exist there |
| `set`, `corpora`, `top_k` | the decision set, the corpora pooled, the cut |
| `metric` | must be `mrr@<top_k>` |
| `variable` | `embedding_model` or `chunker` |
| `arms` | record prefix → declared value: a model name, or `{"chunker_version": …}` only (review A, M3: no header records a separate variant; the version names it) |
| `pair` | `{baseline, candidate}`, for a rule applied on its own |
| `after` + `arms_by_verdict` | instead of `pair`: the rule applied first, which must be judged on the same set and corpora (review A, N2), and the pair each of its verdicts (`ADOPT`, `REJECT`) selects |
| `clauses` | `[{id, level: file\|symbol, scope: pooled\|each_corpus, min_delta}]`; holds when Δ ≥ `min_delta` − `allowance` |
| `allowance` | in [0, 1e-6); M2's is 1e-9 |
| `description` | optional prose |

Unknown keys are refused, so a clause type the schema lacks cannot be ignored silently: a rule
that needs one extends the schema, with tests, in its own plan (QD7, QD9).

**The verdicts:** `holds()` is tested on M2's committed numbers at exactly `min_delta − 1e-9`
(holds) and 2e-9 past it (fails), per clause. End to end, each clause is driven by records to
exactly its bar (+0.03 = 1.35/45; 0; −0.11 = −1.65/15: adopts) and one rank step past it
(rejects). **The rule order:** `TestTheRuleOrder` builds the candidate and current M2 pairs to
give opposite verdicts, and shows that chunk-shape `ADOPT` judges the `candidate-*` arms and
`REJECT` the `current-*` arms.

**It prints** per rule: per corpus and pooled, MRR, recall and rank-1 at 5 for file and symbol;
- MRR@20 from the `boosted` list joined to its legs by `chunk_id` (or "unavailable" below 20
  ranked results). Each corpus is scored with its own `exact_paths`, pooled included (review A,
  N1; `test_pooled_mrr_at_20_scores_each_corpus_with_its_own_exact_paths`).
- The per-question table.
- Answers tied with the cut at 2e-6, reported only.
- Each clause with its Δ, bar and result, and `VERDICT: ADOPT|REJECT (rule)`.
- First, **"Order of record verified"**: each commit that changed a rule and each that brought
  a set's questions into a spec, with its date, for a protocol to cite (review A, N3).

Exit 0 when every rule adopted, 1 when any rejected. `decide-fixture-run.txt` holds three real
CLI runs on the test fixtures (exit 1, 0 and 2).

**`vector_sha256` moved to `chunk_digest.py`,** one definition; the harness keeps the name as

## 6. ISS-041: one MRR on every Python

Raised by the coordinator mid-plan: the worker images run Python 3.11, CI runs 3.12, and 3.12
changed how the built-in `sum` adds floats. Since `decide.py` compares MRRs through
`scoring.aggregate`, a verdict must not depend on the interpreter.
- **`scoring.aggregate` adds reciprocal ranks with `math.fsum`** (correctly rounded, so the same
  double everywhere); `decide.py`'s MRR@20 does too. Δ is one IEEE subtraction, also
  version-independent. The tolerances stay explicit: M2's 1e-9 allowance, unchanged.
- **`test_tripwire.py`'s reference copies** still use `sum`, as the 22-03 summaries were written
  with it.
  - Their counts are compared exactly, and their MRR within `SUM_ROUNDING = 1e-12`.
  - The bound's comment justifies it from both sides (review B, n2). It is ~200x the analytical
    worst rounding, ~5e-15 in a mean of 45, and the measured worst is 5.6e-17. It is also far
    below a rank step (~1.1e-3) and M2's 1e-9.

## 9. Deviations

1. **The order check is stricter than its words.** The plan names "the commit that added the
   rule's JSON"; `decide.py` requires *every* commit that changed it to precede the questions.
   - A rule edited after its questions is refused too, even for its description. The template
     now says so.
   - A merge commit counts only when it differs from every parent, so QD12's protocol merge passes.
   - Since the review round, a spec must also sit at its path before its questions arrive (I1).
2. **Refusal 5 covers more than its list:**
   - an arm's header against the rule (set, `top_k`, corpus, the declared variable);
   - every pair an after-rule could select;
   - for a chunk comparison, equal query-vector hashes per question;
   - since the review round, `retrieval_code_version` and `corpus_tree_digest` (I3).
3. **Refusal 1 also refuses** a symbol clause over a question naming no symbol, since the
   protocol's symbol MRR is "over the same 45".
4. **`vector_sha256` moved** from the harness to `chunk_digest.py`, so the judge does not carry
   a copy (the checklist's "helper carrying its own copy" lesson).
5. **The independence check treats a symbol-less question as targeting its file.** That is
   stricter than `(path, symbol)` read literally; no committed question lacks a symbol.
6. **`decide.py` buffers its output,** and prints nothing but the refusal when it refuses.
7. **ISS-041 (section 6) was added mid-plan at the coordinator's request.**
