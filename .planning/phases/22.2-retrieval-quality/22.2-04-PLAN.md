**Lessons that apply here** (review checklist; 22.2-01 to 22.2-03 and 22.2-07):

  class cannot show the header keeping its decorators; one with no nested

  script from a committed record.

**The shape, one definition** (`workers/chunker/shape.py`):
- `ChunkShape`, a frozen dataclass with one boolean per part, plus
  `split_over_tokens: Optional[int]`:
  - `class_header_only` (part 1), `drop_nested_duplicates` (part 2),
    `python_docstring_once` (part 3), `split_over_tokens` (part 4),
    `chunk_go_types_and_consts` (part 5), `chunk_ts_type_declarations`
    (part 6).
- `SHAPES`: a registry of named shapes. `"current"` has every part off and
  must reproduce today's chunks exactly. `"candidate"` is the bundle; until
  Task 2 freezes it, it holds parts 1–3 on and 4–6 off.
- `shape_from_spec(text)`: `"current"`, `"candidate"`, or an exploration
  spec such as `"current+class_header_only+split_over_tokens=1500"`, so
  Task 2 can run any combination from one commit. The **name** recorded in a
  header is the spec text, normalised (parts sorted).
- `SemanticChunker(shape: ChunkShape = SHAPES["current"])`. Every part reads
  `self.shape`; nothing else selects behaviour.

**The parts:**
1. **`class_header_only` (ISS-026).** For a class whose methods have chunks
   of their own, the `class` chunk's text is:
   - its decorators and its `class …:` / `class … {` line (QD6: from the
     first decorator);
   - its docstring as it stands in the source (Python) — or nothing more,
     for TS, whose JSDoc is already the docstring;
   - its body's non-method statements: attributes, assignments, fields;
   - a method list, one line per method, each the method's signature line
     (decorators omitted, they are in the method's own chunk).

   The chunk keeps the class's span (`start_line`, `end_line`), its
   breadcrumb, its metadata and its docstring. A class with no method chunks
   is unchanged. **The `class_summary` chunk:** the first version keeps it
   unchanged. Whether it should go, now that the header lists the methods,
   is one exploration step in Task 2 (`drop_class_summary`, a seventh flag),
   not a guess here.
2. **`drop_nested_duplicates`.** A function chunk whose definition sits
   inside another function's chunk span is not emitted (its text stays in
   its parent's chunk). A Go struct declared inside a function is not
   emitted as its own chunk. A method is never "nested": its parent is a
   class, not a function.
3. **`python_docstring_once`.** For Python, the docstring stays in the
   chunk text and is **removed from `metadata["docstring"]`** of that chunk,
   so `embedding_text` sees it once. It is expressed in the chunk, never in
   `embedding_text`, so the chunk-set digest (which hashes the docstring,
   22.2-01 §2) sees the change. `ClassSummaryGenerator` reads a method's
   docstring from metadata (`summary_generator.py:278`), so under this
   part it reads the method's docstring through one helper that takes it
   from the parser's result instead; the summary text is unchanged. A test
   pins that.
4. **`split_over_tokens=N`.** A function chunk whose embedded text exceeds N
   tokens (`EmbeddingGenerator.tokens_over_limit`'s counting, one rule) is
   split at top-level statement boundaries of its body into parts of at
   most N tokens. Every part carries the function's breadcrumb, docstring
   and `function_name`, and `metadata["part"] = "i/n"`. The first part
