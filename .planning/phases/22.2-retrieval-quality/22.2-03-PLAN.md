**The blind writers: who they are and what they can reach.**
- **Two writer agents, 15 questions each,** run one after the other.
  - Writer 2 is given writer 1's `(path, symbol)` list, to avoid. It never
    sees writer 1's questions.
  - QD10 allows one or two. Two keeps each writer's context small.
- **Their tools are Read, Grep and Glob only.**
  - That means no shell, no web, no MCP, and no writing.
  - They are defined as a project agent, `.claude/agents/blind-question-writer.md`
    (`tools: Read, Grep, Glob`), created and committed in Task 1. Approving
    this plan approves that file.
  - **If the environment cannot restrict an agent's tools, stop and raise it
    on the PR.** Do not substitute an unrestricted agent.
- **What they may read: the pinned checkout, and nothing else.** The checkout
  is at `<corpora-dir>/linkwarden`, outside this repository.
  - Not RAG-Doc's code, the harness, a database, the web, any retrieval
    result, `22.2-RESEARCH.md`, or any other question file.
- **What they are told.** The prompt is committed verbatim as
  `22.2-03-records/writer-prompt.md`. It says:
  - the root's absolute path, and that every Grep and Glob call must pass it
    explicitly. Without a path they search the session's working directory,
    which is this repository;
  - what to write: questions a developer new to this codebase would ask, each
    answered by one named declaration;
  - for each question: the question, the exact path relative to the root, the
    answering symbol, and `path:line — why` as evidence;
  - **the phrasing:**
    - the way a newcomer asks;
    - never the symbol's name, the file's name, or a distinctive identifier;
    - about a third deliberately use words the code does not;
  - **the kinds:** a mix of "where", "how", "what happens when" and "what
    decides";
  - **the spread:** at most five per package. A package is the file's
    directory cut to its first four path segments (`apps/web/lib/api`,
    `apps/web/components/ModalContent`), or fewer when the directory is
    shallower (`apps/web/pages`, `packages/router`);
  - **the symbol's form**, because the answer key must name something a
    reader can point at:
    - one of: a named function, a module-level `const` or `let` bound directly
      to an arrow function or function expression (named by the variable), a
      class, or a class method written `ClassName.method`;
    - never: an anonymous default export, a function passed to another call
      (`wrap(async () => …)`), an object-literal method, a nested function, a
      class-field arrow function, or an interface, type or enum;
    - *(for the reviewer, not in the prompt)* 22.2-02 chunks none of the
      "never" forms except nested functions. Those are excluded because
      22.2-04's candidate may stop chunking them on their own (QD7). A
      question on one would then become unscorable at symbol level partway
      through the phase;
  - where to look: only `apps/web`, `apps/worker` and `packages`, and never a
    `.d.ts` file, a test or `e2e/`;
  - writer 2 only: the `(path, symbol)` pairs to avoid;
  - to answer with a JSON array in the final message, and to write nothing
    else.
- **What they are not told:**
  - that retrieval exists;
  - what RAG-Doc is;
  - anything about chunks, embeddings or models;
  - which decisions the questions will serve.
- **The audit.** After each writer finishes, its transcript is read, meaning
  every tool call in the agent's output file.
  - `22.2-03-records/audit_writer.py` writes `writer-audit.txt`: each call's
    tool and path, and whether that path is under the root.
  - **Any** of these voids that writer's batch:
    - a call outside the root;
    - a Grep or Glob with no explicit path;
    - a tool other than the three.
  - A voided batch is discarded, with the reason recorded, and a fresh writer
    with the same prompt replaces it.

**How these 30 stay out of any deciding set:**
- **They are exploration sets.**
  - They carry `set: tuning` (odd ids) and `set: holdout` (even ids).
  - No rule is ever judged on them. M2 and the chunk-shape rule are judged on
    the shared set only (QD8, QD10).
  - 22.2-04 explores on the tuning half, and looks at the holdout half only
    after a change is made (the harness's rule).
- **The shared set does not exist yet, and cannot be written from these.**
  - 22.2-05 writes it only after both its rules are committed.
  - Its writers are new agents, set up as here. They receive only the list
    of `(path, symbol)` pairs already targeted, from 22.2-07's
    `--list-targets`, and never these questions' texts, answers or results.
- **The separation is mechanical, not only procedural.**
  - 22.2-07's independence check refuses any decision-set question that
    targets a `(path, symbol)` another set of the same corpus targets.
  - A leak of a target into the shared set fails `validate_spec`.
- **No one who has seen a result writes a question.** Writers have no
  retrieval access by construction. Task 2's executor, who does see the
  baseline, writes no question of any set.
- **Nothing leaks the other way.** This plan's writer prompt names no
  candidate and no decision.

**Lessons that apply here** (review checklist):
- **The commit order is the evidence.** The spec, with its split rule, is
  committed before any question; the questions before any ingest. A question
  is never edited after a retrieval result for it exists.
- **Edit the answer key, not the question, and only before measurement.**
  - A symbol spelled differently from the chunker's name for the same
    declaration may be corrected, and the correction is recorded.
  - A question that echoes its symbol goes back to **its writer** to
    rephrase.
- **Environment facts:**
  - a scratch container, never compose's, never port 5434, removed after;
  - every measuring connection is `rag_doc_app`, recorded;
  - never print `OPENAI_API_KEY`: check it by its length;
  - `.gitignore` ignores `*.log` and `logs/`, so records are `.txt`, `.json`
    or `.gz`.
