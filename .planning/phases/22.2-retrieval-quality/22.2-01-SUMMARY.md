## 2. The definitions, as built

- **`chunk_row(file_path, start_line, end_line, chunk_type, content, breadcrumb, docstring)`**
  gives `(file_path, start_line, end_line, chunk_type, sha256(content), sha256(breadcrumb),
  sha256(docstring))`, with `None` hashed as `""`.
- **`chunk_set_digest(rows)`** is SHA-256 over the rows, sorted, as compact JSON. Duplicate rows
  are kept, so it is the digest of a multiset.
- The database read is `chunk_digest.DB_ROWS_SQL`: `metadata->>'breadcrumb'` and
  `metadata->>'docstring'` `WHERE repository_id = %s AND embedding_model = %s`, run by the harness
  as the measuring connection under `require_tenant`.
- **`chunker_version()`** is the first 16 hex characters of a SHA-256 over two things:
  - each non-test `.py` under `workers/parser/` and `workers/chunker/`: its relative path and the
    SHA-256 of its bytes with CRLF read as LF;
  - the installed versions of `tree-sitter` and the four grammar packages.

  Today's is `a1a44e8d682e21bb`.
- **Pins:** `tree-sitter==0.25.2`, `tree-sitter-python/-go/-javascript==0.25.0`,
  `tree-sitter-typescript==0.23.2` and `tiktoken==0.12.0`, in `requirements.txt`. The census reads
  them from there and exits 2 on any mismatch.

## 5. The tripwire

`tripwire.py --before DIR --after DIR --corpora … [--before-prefix before] [--after-prefix after]`.

**It refuses with exit 2, comparing nothing, when:**
- the question ids differ, or a question's text, set, path or symbol differs;
- a record's ranks are not what its own final list gives under `scoring.ranks`;
- a measuring connection is a superuser, bypasses RLS, or is unrecorded (`compare_runs.connection_problems`);
- any query failed;
- a question's query-vector hash differs between the sides;
- the embedding model, `top_k`, `boost_config` or `exact_paths` differ;
- a header has no `chunk_set_digest`;
- a final list is not a list of results, or any input the reader cannot use. That case was added
  in the review round (A7), so a malformed record exits 2, never 1.

**What it computes:** corpus × set × level × metric (recall@k, rank-1, MRR@k) from the
recomputed ranks, with `scoring.aggregate`. A number "falls" when after < before − 1e-9.

**What it prints:**
- the table;
- every worsened and improved question;
- both digests per corpus, with "identical chunk set" marking a control.

**Exit:** 0 when nothing fell, 1 when anything did, 2 when the input is refused.

**Tests** (`tests/test_tripwire.py`, 31):
- nothing fell gives 0;
- one MRR fall of 0.0011 gives 1;
- a rise only gives 0;
- a count falls by one question;
- `.gz` records are read;
- equal digests are flagged;
- **one test per refusal, 17 in all, each exit 2:**
  - the plan's 13;
  - deviation 3's set, path and symbol. They were untested until the review round (B1),
    and the first version of this summary claimed "one test per refusal (13)";
  - a malformed final list;
- an unforeseen malformed header exits 2, not 1.

The formula test reads the ranks in 22-03's `pgvector-{self,miniflux,mealie}.jsonl.gz`:
- per set and for `all`, `scoring.aggregate` equals both old copies, from `4000acc`, kept as
  test-local references;
- for `all` it equals the committed `.summary.json`;
- `harness._score` and `compare_runs.score` no longer exist. The harness, `compare_runs.py` and
  `tripwire.py` all hold the one `scoring.aggregate`.

## 10. Deviations from the plan, each the smallest faithful fix

1. **The chunker version reads CRLF as LF.** The plan says "the bytes". A Windows checkout and
   `git archive` convert line endings (`core.autocrlf=true`), so raw bytes would name one commit
   two ways. A test pins this.
2. **The harness gains `--self-commit`**, as the census has, because the live proof ingests from
   an export with no `.git`.
   - `ingestion_runs.commit_sha` is `NOT NULL`, so a `self` ingest whose commit is unknown still
     records `"harness"`, as before.
   - `tree_commit` returns None for a directory that is only inside another checkout.
3. **`tripwire.py` takes `--before-prefix`/`--after-prefix`** (defaults `before`/`after`). They
   match the `before-<c>`/`after-<c>` names 22.2-02's plan uses.
   - It also refuses a differing set, path or symbol per question, not only a differing id or
     text: either would compare different targets.
4. **`--no-qdrant` still reads `exact-<c>.json`.** It is (c)'s cut pool, and 22.2-01's live proof
   produces it.
   - The mode and tolerance lines print only when not at the default, so the default output stays
     byte-identical.
   - In that mode the sides are named by their prefixes.
5. **`files_with_declarations_but_no_named_chunk` uses a parity simulation for Go and Python too.**
   The research had TypeScript's only, and the plan's test names fixtures in all three languages.
6. **The `raised` test makes `extract_functions` raise,** not `parse_file`: the census parses each
   file again for its parse-error counts.
7. **`scoring.aggregate` landed in Task 2's commit,** because the harness's edits were made in
   one pass. Task 3's verification (the 22-03 re-judge, the formula test) covers it.
8. **The census scopes its log capture to each call** (`2c39224`).
   - The first version quietened the `workers` logger for the whole process. In the full suite
     that silenced two `test_answer_generator.py` tests that read a warning.
   - A test now pins that a census leaves logging as it found it.
   - The reproduction and T1-M2 were re-run on the final file.
9. **`reproduce_census.py` is a new script** beside the records, not `22.2-records/reproduce.py`.
   The old script counts extra fields as failures, and this plan's fields are extras by design.

None touches a locked decision (QD*, QA*, M2).
