  <name>Task 1: Audit + complete Supabase webhook signature verification</name>
  <files>services/backend/pkg/auth/webhook.go, services/backend/pkg/auth/webhook_test.go</files>
  <action>
**Sub-step A: Audit.** Read `pkg/auth/webhook.go`. Determine:
- Is HMAC-SHA256 signature verification implemented against `X-Webhook-Signature`?
- Does it use `crypto/hmac` + `crypto/subtle.ConstantTimeCompare` (constant-time) or a naive `==`?
- Is the shared secret sourced from `SUPABASE_WEBHOOK_SECRET` env var?
- Does the handler validate `Content-Type: application/json` and enforce a small body size limit (say 64KB)?

**Sub-step B: Complete or refactor.** Based on the audit, either finish the stubbed pieces or refactor for constant-time comparison. Handler should:
- Read the raw body once, into a bounded buffer.
- Compute HMAC-SHA256 over the raw body with the shared secret.
- Compare against `X-Webhook-Signature` header using `subtle.ConstantTimeCompare`.
- On mismatch: return 401 with a generic "unauthorized" message (no signature leakage in error).
- On match: decode into `SupabaseWebhookEvent`, dispatch by `event.Type` (only `INSERT` on `auth.users` in scope for 19-01), log at info level, return 202 Accepted with a stable event id in the response body.

**Sub-step C: Unit tests.** Cover:
1. Valid signature + valid payload → 202.
2. Missing `X-Webhook-Signature` header → 401.
3. Malformed HMAC (wrong secret) → 401.
4. Correct signature but body decodes to junk → 400.
5. Body over the size limit → 413.
6. Constant-time comparison test — build two signatures that differ by one byte at increasing positions and verify no timing side-channel via a rough benchmark (this is a smoke test, not a hardness proof).

Avoid: Reflecting the received signature back in any error response. Avoid: logging the raw signature or the secret.
  </action>

**Sub-step A: Add `httprate` dep.** `go get github.com/go-chi/httprate`.

**Sub-step B: Create `pkg/auth/abuse.go`.** Two exported functions:
- `RateLimitWebhook() func(http.Handler) http.Handler` — thin wrapper around `httprate.LimitByIP(10, time.Minute)` with a 429 response that includes a `Retry-After` header. Configurable via `WEBHOOK_RATE_LIMIT_PER_MIN` env var (default 10).
- `IsDisposableEmail(addr string) bool` — checks the domain against a small embedded blocklist (Curated list of ~20 common throwaway providers: `mailinator.com`, `10minutemail.com`, `guerrillamail.com`, `tempmail.io`, `throwawaymail.com`, etc. Include a comment pointing at a maintained list for future updates, but do not add a dependency.)

**Sub-step C: Wire OAuth handlers on router.**
In `pkg/api/router.go`, inside `NewRouterWithValidator`, after existing public routes:

```go
oauthConfig := auth.NewOAuthConfig()
stateStore := auth.NewStateStore(redisClient) // TODO: source redisClient from constructor
r.Get("/auth/github/login", auth.HandleGitHubLogin(oauthConfig, stateStore))
r.Get("/auth/github/callback", auth.HandleGitHubCallback(oauthConfig, stateStore, dbpool))
r.Get("/auth/gitlab/login", auth.HandleGitLabLogin(oauthConfig, stateStore))
r.Get("/auth/gitlab/callback", auth.HandleGitLabCallback(oauthConfig, stateStore, dbpool))
```

Note: `redisClient` isn't currently a `NewRouterWithValidator` parameter. Add it as one; update `NewRouter` sugar and `main.go` caller. Redis is already a project dep for other things (`state_store.go` already uses it).

**Sub-step D: Attach webhook middleware chain.** Update the existing webhook route mount:

```go
r.With(auth.RateLimitWebhook()).Post("/webhooks/supabase", webhookHandler.HandleSupabaseWebhook())
```

The disposable-email check runs inside the handler on the `user.created` payload's email field, not as middleware (needs body access).

**Sub-step E: Unit tests.** In `pkg/auth/abuse_test.go`:

2. `IsDisposableEmail` returns false for `alice@example.com`.
3. `RateLimitWebhook` returns 429 with `Retry-After` on the 11th request from the same IP inside one minute.

Avoid: making `IsDisposableEmail` case-sensitive (lowercase the domain first). Avoid: hardcoding IPs in the rate-limit test — use `httptest.NewRequest` and set `X-Forwarded-For` (chi's RealIP middleware is already in the chain).
