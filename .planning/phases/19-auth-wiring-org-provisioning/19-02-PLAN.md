**Constraining decisions (from 19-CONTEXT and 19-01 SUMMARY):**
- Provisioning is called from the webhook handler completed in 19-01. Signature verification, rate limiting, and email-domain block already fire before this code runs.
- Idempotency mechanism: `INSERT ... ON CONFLICT (supabase_user_id) DO NOTHING RETURNING id`. Replays of the same event produce zero rows on the second call; that's the signal to skip provisioning and return 202.
- Starter org name: `<email local-part>'s Workspace`. Slug: `sanitize(<email local-part>) + '-' + short-hex`. Sanitize per the `organizations.slug CHECK (^[a-z0-9-]+$)` from migration 000001.
- Every provisioned user gets a starter org with `role=owner`. Multi-org users happen via 19-04.
- Every DB write goes through tenant scope. Organizations are exempt from RLS + trigger (per 17-03 Option A), so the initial org insert doesn't need a scope. Membership, project, and subsequent tenant-scoped rows go under `TenantScope`/`require_tenant` equivalent — but this plan only creates organizations + users + memberships. Projects/repos come from Phase 20.

Prediction: it strips or splits on `@` and then does a `strings.ReplaceAll` on invalid chars that produces a leading dash when the original had a dot (`my.name@example.com` → `my.name` → `-name` after replacing dots with dashes).

**Sub-step B: Fix.** The slug rule (from migration 000001): `^[a-z0-9-]+$` with additional convention: no leading/trailing dashes, no consecutive dashes.

Correct algorithm:
1. Take the email local part (`strings.Split(email, "@")[0]`).
2. Lowercase.
3. Replace runs of any non-`[a-z0-9]` character with a single dash.
4. Trim leading and trailing dashes.
5. If empty, fall back to `"user"`.

Add these edge cases to the existing test:
- `my.name@example.com` → `my-name`
- `alice+tag@example.com` → `alice-tag`
- `_leading_underscore@example.com` → `leading-underscore`
- `___@example.com` → `user`
- Very long local part (200 chars) → truncated to 30 chars, no trailing dash after truncation

**Sub-step C: Extract short-hex helper if not present.** `pkg/testing/isolation/fixtures.go` has a `shortToken()` helper (unexported). For production use, either add an exported `RandomSlugSuffix()` in `pkg/auth/` or inline the logic. The organization slug is `sanitizedLocal + "-" + shortHex()`.

```go
func (p *UserProvisioner) ProvisionOAuthUser(ctx context.Context, event UserCreatedEvent) (User, bool /*created*/, error) {
    var user User
    err := p.db.QueryRow(ctx, `
        INSERT INTO users (supabase_user_id, email, full_name)
        VALUES ($1, $2, $3)
        ON CONFLICT (supabase_user_id) DO NOTHING
        RETURNING id, supabase_user_id, email, full_name
    `, event.SupabaseUserID, event.Email, event.FullName).Scan(...)
    if errors.Is(err, pgx.ErrNoRows) {
        // Replay — fetch existing.
        err = p.db.QueryRow(ctx, `SELECT ... FROM users WHERE supabase_user_id = $1`, ...).Scan(...)
        return user, false, err
    }
    return user, true, err
}
```

**Sub-step B: Extend `CreateOrganizationForUser` for idempotency.** Same pattern: `ON CONFLICT DO NOTHING` on the `organizations.slug` uniqueness constraint. If a slug collision happens (very rare given the random suffix), retry once with a fresh short-hex.

**Sub-step C: Wire into webhook handler.** Inside the `case "INSERT" + table=="auth.users"` branch:

```go
event := UserCreatedEvent{
    SupabaseUserID: ..., Email: ..., FullName: ...,
}
if auth.IsDisposableEmail(event.Email) {
    log.Warn("rejecting disposable email domain", "email", event.Email)
    http.Error(w, "email domain not allowed", http.StatusUnprocessableEntity)
    return
}
user, created, err := provisioner.ProvisionOAuthUser(ctx, event)
if err != nil { /* 500 */ }
if !created {
    log.Info("webhook replay — user already provisioned", "user_id", user.ID)
    render.Status(r, http.StatusAccepted)
    render.JSON(w, r, map[string]string{"status": "already_provisioned", "user_id": user.ID.String()})
    return
}
org, _, err := provisioner.CreateOrganizationForUser(ctx, user)
if err != nil { /* 500 */ }
// Log the (user, org) tuple at info level for audit trail.
render.Status(r, http.StatusAccepted)
render.JSON(w, r, map[string]any{
    "status": "provisioned",
    "user_id": user.ID.String(),
    "organization_id": org.ID.String(),
})
```

Avoid: swallowing DB errors as "already exists." Distinguish `pgx.ErrNoRows` (replay, safe) from real errors (500). Avoid: doing all of this in one transaction — user and org creation are logically separate; a failed org creation should NOT roll back the user row (Supabase already committed the user in its auth schema; our row must exist to close the loop even if org creation retries later).
