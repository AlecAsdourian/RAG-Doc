<objective>
Give the worker a safe way to get a repository's code, without ever giving it
the GitHub App's private key. The work splits across the two services:

- **The backend (Go)** keeps the key. On an **internal-only** listener, it mints
  a **one-hour installation token scoped to one repository with
  `contents: read`**. It mints only for a caller presenting a job id and that
  job's lease, while the job is `running` under that lease.
- **The worker (Python)** asks for that token and downloads the repository as a
  tar archive through the GitHub API, at an exact commit. It extracts the
  archive safely into a per-job directory, enforces the v1 caps, skips
  secret-looking, vendored, generated and binary files, and cleans up after
  itself.

Hostile-archive tests prove the extraction. Redaction tests prove no token or
download link reaches a log line or `last_error`.

**Output:**
- `github.Client.RepositoryToken`;
- a new `pkg/internalapi` package and its internal listener;
- a new `workers.fetch` package;
- tests, and `docs/internal-api.md`.

**Estimate:** 14–20 h, 2 tasks.
</objective>

**Locked decision this plan implements: P10**, from four of the user's answers:
- **U4:** the backend keeps the key; the worker gets a one-hour, one-repository,
  read-only token checked against the job's lease.
- **U5:** fetch an archive, not a `git clone`. The worker image has no `git`
  (measured).
- **U6:** archive ≤ 500 MB; ≤ 20,000 indexable files; ≤ 1 MB per file;
  ≤ 100,000 chunks. The last cap is enforced after chunking, in 22-05.
- **U7:** a deny-list of secret-looking files.

P10 also fixes the mechanics: extract with `tarfile`'s `data` filter into a
per-job temporary directory, never follow symlinks, remove the directory in
`finally`, and sweep stale ones when the worker starts.

**⚠ One interpretation this plan makes, flagged for the coordinator.** U6 says
"archive ≤ 500 MB". This plan applies 500 MB **to both the bytes downloaded and
the bytes the archive expands to**.
- **Why:** only the expanded limit stops a decompression bomb, where a small
  download expands without bound.
- **If the user meant the download only,** the bomb guard needs a number of its
  own, and Task 2 names where it goes.

**Verified facts** (`22-RESEARCH.md` Q8, from GitHub's documentation, fetched):
- **Scoping.** `POST /app/installations/{id}/access_tokens` accepts
  `repository_ids` (up to 500) and a `permissions` object, and the token expires
  one hour after creation.
- **Today's tokens are unscoped.** The Go client sends **no body**
  (`client.go:263-264`), so each token covers everything the installation can
  reach. That is fine for the backend's own listing calls and wrong for handing
  to a worker.
- **The archive.** `GET /repos/{owner}/{repo}/tarball/{ref}` redirects to a
  download link that, for a private repository, "expire[s] after five minutes".
  No size limit is documented.
- **[not verified]** whether that link carries a credential of its own. Treat it
  as a secret: never log it, and never put it in an exception message.

**The job lookup is queue-wide.** Like `claimSQL`, it must never sit on the
public router.
- The token route finds its job by id, lease owner and live lease, **before** it
  knows the tenant. `ingestion_jobs` has no row-level security (21-CONTEXT L5).
- So the route lives in a **new package, `pkg/internalapi`**, served by a
  **second listener**, not by `pkg/api`'s router. `docs/api-ingestion-jobs.md`
  keeps the rule that queue-wide SQL never reaches a public handler; this
  follows it.
- **The listener's address.** It binds `INTERNAL_ADDR`, default
  `127.0.0.1:8081`. In compose it is exposed on the compose network only: it is
  **never** in `ports:`. Phase 24 already carries "keep the token route
  internal" as a research topic.
- **What `lease_owner` is worth.** It is the credential the worker presents, and
  it is a UUID4 that no API returns: 21-07 deliberately left it out of the job
  response.
- **The residual risk (P10, stated):** a process with the worker's database
  access can read every running job's lease. The tokens such a process could
  obtain are still scoped to one repository, read-only, and short-lived. That is
  far narrower than holding the key.

**The CI isolation scanner will flag the new `POST`.**
`check-isolation-tests.py:70-71` matches `.Post("/…"`. Write
`repository_token_isolation_test.go` **on purpose**, cross-tenant case
included, and mutation-check it. Do not use a skip marker.

**Lessons from Phase 21 that apply here:**
- **A test that reads no log record cannot catch a logging bug.** Every "never
  logged" claim is tested against **captured log output**: an `slog` handler
  writing to a buffer in Go, and `caplog` in Python. Use a realistic token
  (`ghs_` + 36 characters) and a download link carrying `?token=`.
- **Neuter; do not delete.** To mutation-test the lease fence, replace
  `AND lease_owner = $2` with `AND $2::text IS NOT NULL`. Deleting it changes
  the statement's arity, and every test then fails for the wrong reason
  (21-07's M1a).
- **Ask what the fixture cannot distinguish.** Each hostile archive must be
  asserted to **contain** its hostile member before it is fed to the extractor,
  by listing it with `tarfile`. An archive that silently lost its symlink when
  it was built tests nothing.
- **An assertion inside `finally` replaces the exception propagating out of the
  block.** The temporary-directory cleanup test asserts **after** the `with`
  block, never inside `finally`.
- **Commit before mutating; prove each mutation landed.**
- **Environment facts:** the CRLF test fails locally only; point
  `DATABASE_TEST_URL` at a scratch pgvector container, not 5434; run `-race` in
  `golang:1.25`; the workers venv has `httpx` 0.28 (installed through `openai`),
  and this plan makes it an explicit requirement.

  <files>services/backend/pkg/github/client.go, services/backend/pkg/github/client_test.go, services/backend/pkg/internalapi/repository_token.go, services/backend/pkg/internalapi/repository_token_isolation_test.go, services/backend/pkg/api/router.go, services/backend/main.go, docs/internal-api.md</files>
  <action>
**`github.Client.RepositoryToken(ctx, installationID, githubRepoID int64) (ScopedToken, error)`.**
- It posts `{"repository_ids":[githubRepoID],"permissions":{"contents":"read"}}`
  to the access-tokens endpoint, signed with the App JWT.
- It returns the token and `expires_at`.
- It then calls `GET /repositories/{githubRepoID}` **with the new token** and
  returns `full_name`, `default_branch` and `private`. That proves the token
  reaches the repository, and it survives a rename.
- **No cache.** A job asks once per run, and a cached scoped token outliving
  its job is exactly what U4 exists to avoid.
- Errors pass through the existing `redactSecrets` (`client.go:611-660`).

**`pkg/internalapi`: `POST /internal/jobs/{id}/repository-token`**, body
`{"lease_owner": "…"}`.
1. **Find the job.** An unscoped read:
   ```sql
   SELECT organization_id, repository_id FROM ingestion_jobs
   WHERE id = $1 AND lease_owner = $2 AND state = 'running'
     AND lease_expires_at > NOW()
   ```
   This is the terminal-write fence plus a **live** lease. A job whose lease has
   expired is someone else's to reclaim. **Every miss returns one byte-identical
   `404`**, whether the id is unknown, the owner is wrong, the job is
   superseded, the lease has expired or the id is malformed. That is 21-07's
   rule: anything else is an oracle.
2. **Check the installation**, in a tenant transaction for that organization:
   the repository's `github_repo_id` and `installation_id`, and the
   installation's numeric id and `suspended_at` / `uninstalled_at`.
   - Uninstalled or missing → `409 {"reason":"installation_uninstalled"}`.
   - Suspended → `409 {"reason":"installation_suspended"}`.
   - The worker already checked at claim time (21-06); this closes the window
     between that check and now.
3. **Mint** with `RepositoryToken`. Respond
   `{"token","expires_at","full_name","default_branch"}`.
4. **Log** one line per mint with the job id, organization, repository, GitHub
   repository id and expiry. **Never the token.**

**`main.go`:**
- Build the GitHub client **once**. Today it is constructed inside the router
  (`router.go:179-187`); move that construction to where both routers can
  receive it.
- Start a second `http.Server` on `INTERNAL_ADDR` (default `127.0.0.1:8081`),
  serving only `pkg/internalapi`'s router, and shut it down with the public one.
- **Without GitHub App credentials, the internal server does not start.** Log
  why at WARN, exactly as the public side degrades today.

**Tests:** `httptest` fakes for GitHub, the isolation harness for the database.
- **Scoping.** The mint request's body carries exactly one `repository_id` and
  `permissions: {"contents":"read"}`. Assert the **decoded body**, not the
  presence of a string.
- **Every 404 case is byte-identical:** wrong owner, superseded, expired lease,
  completed, unknown id, malformed id.
- **Cross-tenant, deliberately.** Org A and org B each have a running job with
  its own lease. A's lease owner with B's job id gets the same `404`, and GitHub
  **receives no mint request** (the fake counts calls). Then B's own
  `(id, owner)` gets `200`.
- **The installation states** (suspended, uninstalled) each return their
  `409` and cause **no mint**.
- **Logging.** With a realistic `ghs_…` token from the fake, the captured
  `slog` output of a successful mint and of a failed mint (GitHub `500` with the
  token echoed in the body) contains **no** `ghs_`.
- **The public router does not serve `/internal/…`.** Asking the public router
  for it gets chi's `404`.

**Mutation checks**, each on a copy, proven present, with results recorded:
- the fence neutered (`AND $2::text IS NOT NULL`) → the cross-tenant case fails;
- `lease_expires_at > NOW()` removed → the expired case fails;
- the `permissions` object dropped from the body → the scoping test fails;
- the redaction bypassed in the mint's error path → the logging test fails.

**`docs/internal-api.md`** records:
- the route, its contract and why it is internal;
- the lease-as-credential argument and its residual risk;
- the byte-identical 404;
- the Phase 24 requirement that the listener is never published.

  <name>Task 2: The worker fetches, extracts and filters an archive safely</name>
  <files>services/workers/workers/fetch/__init__.py, services/workers/workers/fetch/client.py, services/workers/workers/fetch/archive.py, services/workers/workers/fetch/filters.py, services/workers/tests/fetch/test_archive_hostile.py, services/workers/tests/fetch/test_fetch_client.py, services/workers/requirements.txt</files>

**`workers.fetch.client`.**
- `request_token(internal_api_url, job_id, lease_owner) -> RepositoryToken`.
- `RepositoryToken`'s `repr` and `str` are redacted.
- A `404` raises `TokenRefused`, which means the job is no longer ours (22-05
  treats it like a lost lease). A `409` raises `InstallationUnavailable`, with
  the reason.

**`workers.fetch.archive.fetch_repository(token, *, workdir, api_base, limits) -> FetchedTree`:**
1. **Resolve the head.** Before downloading, run `GET /repos/{full_name}/commits/{default_branch}`
   with `Accept: application/vnd.github.sha`. That gives the **full 40-hex
   SHA**, which `ingestion_runs.commit_sha` needs.
2. **Download** `GET /repos/{full_name}/tarball/{sha}`, the exact commit, never
   the branch name, with `Authorization: Bearer <token>`. Use `httpx` with
   `follow_redirects=True`, streamed.
   - **Assert in a test that the cross-host redirect request carries no
     `Authorization` header.** Measure it with the fake server; do not assume
     `httpx`'s behaviour.
   - **Count the downloaded bytes, and abort above 500 MB**, raising
     `FetchRejected("archive exceeds 500 MB")`.
3. **Extract** into `workdir/<job_id>/`, iterating members in streaming mode:
   - **Before extracting each member,** check its header:
     - regular files only; symlinks, hardlinks, devices and FIFOs are skipped
       and counted;
     - the member's size ≤ 1 MB, otherwise skip it and count it;
     - the running total of expanded bytes ≤ 500 MB, otherwise
       `FetchRejected`. *This is the bomb guard. If U6's limit is read as
       download-only, give this total its own constant here.*
   - Then `tar.extract(member, path, filter="data")`, which also refuses
     absolute paths and `..`, as defence in depth.
   - Strip GitHub's top-level `owner-repo-sha/` directory from every path.
4. **Walk** the directory with `os.walk(followlinks=False)`, skipping any link
   through `lstat`. For each file, apply the filters and read it as UTF-8. A file
   that fails to decode, or contains a NUL in its first 8 KB, is binary: skip it
   and count it.
5. **Cap indexable files at 20,000.** More than that raises
   `FetchRejected("more than 20000 indexable files")`.
6. **Return** `FetchedTree(sha, branch, files=[(path, content, language)],
   skipped={reason: count})`.
   - `skipped` holds **counts only**, never paths: the secret-looking ones are
     exactly the paths not to repeat.
   - The language comes from an extension map: `.py`, `.go`, `.js`, `.jsx`,
     `.ts`, `.tsx`, `.md`. Anything else is skipped and counted.

**`FetchRejected`** carries a plain, token-free reason. 22-05 turns it into the
job ending `dead` in one attempt, as U6 requires.

**Cleanup.**
- `fetch_repository` is used as a context manager: the job's directory is
  removed on exit, success or failure.
- `sweep_stale_workdirs(workdir, older_than)` removes job directories older than
  `max_job_duration + lease`, which cannot belong to a live job. 22-05 calls it
  when the worker starts.

**`workers.fetch.filters`.**
- **The U7 deny-list, by base name:**
  - `.env` and `.env.*`
  - `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`
  - `id_rsa*`, `id_dsa*`, `id_ecdsa*`, `id_ed25519*`
  - `.npmrc`, `.pypirc`, `.netrc`
  - `*.tfvars`
  - `credentials*.json`
  - `service-account*.json`
- **Vendored and generated:**
  - directories: `vendor/`, `node_modules/`, `dist/`, `build/`, `.git/`,
    `third_party/`
  - files: `*.min.js`, `*_pb2.py`, `*.pb.go`
  - lockfiles: `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`,
    `poetry.lock`, `go.sum`
  - Go files whose first 20 lines match `^// Code generated .* DO NOT EDIT\.$`
- Each rule has its own test case.

**Hostile-archive tests.** Each archive is built in the test with `tarfile`, and
**asserted to contain its hostile member** before use. Each one must produce the
expected skip or rejection, and nothing may land outside `workdir/<job_id>/`:
- `../escape.py`
- `/etc/abs.py`
- a symlink `link.py → /etc/passwd`
- a symlink to `..`
- a hardlink to a path outside
- a FIFO or device entry
- a 2 MB `.py` file (skipped and counted)
- a gzip that expands past the cap (rejected; **assert the extractor stopped
  within one member of the cap, not after reading it all**)
- 20,001 indexable files (rejected)
- `.env`, `id_rsa` and `server.pem` beside real code (never returned; counted)
- a binary `.py` file (skipped)
- non-UTF-8 content (skipped)

**Client tests**, against a fake API through `httpx.MockTransport` or a local
server:
- SHA resolution, and a download pinned to that SHA.
- **No `Authorization` on the redirect.**
- A download failing on a link carrying `?token=SECRET` produces an exception
  whose message, run through `sanitize_error`, does not contain `SECRET` or the
  link. **Assert on `caplog`'s records**, not only on the exception.
- A `404` from the token route raises `TokenRefused`; a `409` raises
  `InstallationUnavailable`.

**`requirements.txt`:** add `httpx` explicitly. It is installed today only
through `openai`.

**Mutation checks**, each on a copy, proven present, with results recorded:
- `followlinks=True` → the symlink test fails;
- the expanded-bytes counter removed → the bomb test fails;
- one deny-list entry removed → its test fails;
- `filter="data"` removed **and** the member-type check removed together → the
  traversal test fails. With only one of them removed, the other still holds,
  which is the defence in depth, and the result is recorded as such.
