**A fourth ending, and why the three are not enough.** A handler has three
endings today:
- `return` → complete;
- `Unfinished` → defer, and only during a shutdown;
- any other exception → fail, with backoff, `dead` at 5 attempts.

A cap violation is deterministic. As an ordinary failure it would download up
to 500 MB five times over about 81 minutes before dying. U6 says it "ends
`dead`". So add **`Rejected(reason)`**:
- a fenced `REJECT_SQL`, with `WHERE id AND lease_owner AND state = 'running'`
  like every terminal write, writing `state = 'dead'`, the reason (through
  `sanitize_error`) and the `failed` projection;
- `workers.fetch.FetchRejected` becomes a subclass of it.

This **changes Phase 21's documented contract** from three endings to four, so
`docs/api-ingestion-jobs.md` is updated in the same commit.

**Lessons from Phase 21 that apply here:**
- **A test that reads no log record cannot catch a logging bug.** The
  live-proof log check greps the captured output of all three processes, and
  the end-to-end test asserts on `caplog`.
- **An assertion inside `finally` replaces the exception propagating out of the
  block.** Put the handler's workdir cleanup in `finally`, and its assertions
  **after** it.
- **A bare `return` after stopping early writes `completed` over work that did
  not happen** (PR #42's review). When shutting down, raise `Unfinished`. When
  `should_abort()` reports a lost lease, returning is safe, because the runtime
  writes nothing when the lease is lost (`runtime.py`, the `lease_lost` check
  before `complete`). Test both paths.
- **`Unfinished` outside a shutdown is a failure, by design:** 193 re-claims in
  6 seconds when it was not. A fetch precondition is never "unfinished".
- **Neuter; do not delete.** `REJECT_SQL`'s fence is mutation-tested as
  `AND $2::text IS NOT NULL`.
- **Commit before mutating; prove each mutation landed.**

  - the workers venv runs `testcontainers`;

**`workers.ingest.handler.make_full_ingest_handler(deps) -> Handler`.**
`deps` holds the token client, the fetcher, the chunker, the embedding generator,
the workdir and the internal API URL, all injectable for tests. The registered
handler resolves its default `deps` **lazily from the environment on its first
call**, so `__main__`'s rule still holds: it checks the registry before reading
any configuration.

The handler runs four stages. **Between every stage:** if
`ctx.is_shutting_down()`, raise `Unfinished`; if `ctx.should_abort()`, return
`None`.

1. **Fetch.**
   - `report_progress("fetch")`.
   - Request a token with `(job.id, ctx.worker_id)`.
   - `fetch_repository(...)` as a context manager.
   - `TokenRefused` → return `None`, because the lease is gone.
   - `InstallationUnavailable` → raise `Rejected` with its reason. The claim-time
     check already defers a suspension; reaching this means the state changed
     mid-run.
   - Progress: `{files_indexable, skipped:{…counts}}`.
2. **Parse.**
   - `report_progress("parse")`, then `SemanticChunker.chunk_file` for each file.
   - More than 100,000 chunks → `Rejected("more than 100000 chunks")`.
   - Progress: `{files_parsed, chunks}`.
3. **Embed.**
   - `report_progress("embed")`, then `generate_embeddings_for_chunks`.
   - Progress: `{chunks_embedded}`.
4. **Return `write_results(cur)`.** `complete()` runs it in the job's tenant
   transaction (`transitions.py:809-897`), so chunks and completion commit
   together or not at all. In order:
   1. `resolve_ingestion_run(cur, repository_id, sha, branch)`, then
      `attach_ingestion_run(cur, job, ctx.worker_id, run_id)`;
   2. `DELETE FROM chunks WHERE repository_id = %s`. The repository's chunks are
      replaced whole. **This makes a retry of the same run idempotent** (the
      Phase 21 hand-off; ISS-027 for full ingests), and it is what 22.1-02
      narrows to per-file;
   3. insert every chunk with its vector through a **cursor-taking** writer
      function. Add `insert_chunks_on(cur, …)` to `PostgresWriter` beside
      22-02's `insert_chunks`, sharing one column list and one statement
      constant;
   4. mark the run `completed` with its chunk count, on the same cursor.

   Nothing of the handler's opens a transaction of its own
   (`complete()`'s contract).

**The fetch directory is removed in `finally`.**

**`Rejected` in `runtime.py` and `transitions.py`.**
- `class Rejected(Exception)`.
- A `reject(conn, job, worker_id, error)` transition with `REJECT_SQL`: fenced;
  writes `state = 'dead'`, `last_error = sanitize_error(error)`, clears the
  lease, sets `updated_at = NOW()`, and projects `failed`. Tenant-scoped like
  `fail`.
- `_invoke` catches `Rejected` **before** the generic `except Exception`.
- `workers.fetch.FetchRejected` subclasses `Rejected`.

**`handlers.py`:** `REGISTRY["full_ingest"]` and `REGISTRY["incremental"]` are
**both** the full-ingest handler until 22.1-02 distinguishes them. Say so in the
module docstring, which currently describes the empty registry.
