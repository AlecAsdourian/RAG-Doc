<objective>
Move the vector leg of retrieval from Qdrant into Postgres, prove the move
changed storage and nothing else, then retire Qdrant.

**The order is the plan.**
1. **First, still on the Qdrant read path:** record a complete baseline on the
   three benchmark corpora. That means the query vectors (embedded once and
   cached), each leg's top 50, the fused and boosted scores, the final ranks, the
   set of chunks Qdrant holds, and an exact-search top 50.
2. **Then** switch the vector leg to pgvector and record again, against **the
   same scratch database and the same cached vectors**. Judge the two under a
   rule written in this plan before anything is measured.
3. **Only if the gate passes,** retire Qdrant everywhere.

**Output:**
- a trace hook in `QueryEngine`, and `--record`, `--query-vectors` and a compose
  guard in the harness;
- the vector leg in SQL;
- the keyword leg without its latest-run filter;
- the breadcrumb-index proof (this plan owns it);
- Qdrant removed;
- a committed comparison script;
- the equivalence verdict.

**Estimate:** 14–20 h, 3 tasks.

Task 3 touches more than five files, but almost all of them are one-line
removals or deletions. They share a single precondition, the gate's verdict, so
they stay one task rather than being split across plans.
</objective>

**Locked decisions this plan implements:**
- **P5** (correction to D2 §5): iterative scan is load-bearing. The detail,
  decided here: `relaxed_order`, then re-sort the returned rows by their exact
  distance in Python.
- **P6** (U3 + U10): both legs in Postgres; fusion and boosts stay in Python.
- **P15**: Qdrant leaves, **after** the gate.
- **P4** (U3): the model stays ada-002, and a query is never compared across
  models.

**Measured plan shapes, which the fact-check caught and the planner re-measured
on 2026-09-17:**
- **HNSW eligibility needs `enable_sort = off` as well.** With only
  `enable_seqscan` and `enable_bitmapscan` off, a 201-row partition used the
  `repository_id` btree plus a Sort. Adding `enable_sort = off`, with the query
  vector as a **bound constant**, gave `Index Scan using …_embedding_idx`.
  - **What that proves:** the HNSW index **can** serve this exact query shape,
    meaning the operator class matches, the vector is a bound parameter rather
    than a subquery, and the scan is on a pruned partition.
  - **What it does not prove:** that the planner will **choose** HNSW at
    production sizes. At benchmark sizes it rightly chooses exact search. That
    is 22.1-05's recall test, which asserts the plan at scale.
- **The breadcrumb GIN proof needs its own shape.** GIN supports only bitmap
  scans, and with only `enable_seqscan` off the planner picked a btree, as the
  fact-check measured.
  - **What works, measured:**
    - run against **one partition, as the superuser** (so no row-level-security
      predicate offers a btree alternative);
    - use **only the breadcrumb predicate**;
    - set `enable_seqscan` and `enable_indexscan` off;
    - the matching expression then gives `Bitmap Index Scan` on the
      `COALESCE(breadcrumb, '')` index.
  - **With a mismatched expression** (bare `breadcrumb`), the same shape gave
    `Seq Scan`. So the test distinguishes a match from a mismatch.
  - **This plan owns that proof** (fact-check c6: nothing owned it). 22-02 only
    creates the index.

**Isolation tests must not run as the superuser** (fact-check c3). A superuser
bypasses row-level security even under FORCE.
- The `dsn` fixture that forces `options=-c role=rag_doc_app` lives in
  `test_job_worker_runtime.py:98-113`.
- **Lift it into `tests/isolation/conftest.py` as `app_dsn`**, and use it
  wherever a test builds a `QueryEngine` or a retriever from a DSN.
- Each isolation test asserts `rolsuper = false` and `rolbypassrls = false` for
  its own connection.

**What the gate needs, and why it is recorded first** (fact-check c4).
- **The harness JSON holds too little.** It keeps only final ranks
  (`rag_quality_harness.py:540-543, 598-603`): no query vectors, no per-leg
  results, no fused scores.
- **The query vectors must be identical.** Each measure run re-embeds every
  question, and whether ada-002 returns identical vectors across calls is **not
  verified**. So the vectors are embedded **once** and cached, and both runs use
  the cache.
- **Classes (b) and (c) below need the Qdrant leg's top 50, the exact top 50 and
  the fused scores.** None of these can be recomputed once `qdrant-client` is
  gone, so they are recorded while Qdrant is still there.
- **The corpora directory is resolved relative to the repository**
  (`:128-130`), so every harness call passes `--corpora-dir` explicitly.
- **Nothing is compared across databases.** The baseline and the pgvector
  measurement use **one** scratch database, so chunk ids and vectors are
  identical. If the session breaks between Task 1 and Task 2, redo Task 1; it
  costs about $0.10.

**What stays unverified, and how the gate copes:**
- **Qdrant's `full_scan_threshold` behaviour.** Qdrant may have searched
  approximately; class (b) measures rather than assumes it.
- **ada-002 determinism.** The cache makes it irrelevant.

**The harness defaults to port 5434** (`:123`). That is compose's mapping, and
it is **currently bound by another project's container (`brickt-1239-pg`)**.
Task 1 adds a guard **before any `--ingest`**: `--ingest` and `--clear` refuse
port 5434 unless `--allow-compose` is passed. Nothing in this plan passes it.

**Lessons from Phase 21 that apply here:**
- **A helper carrying its own copy of a predicate is blind to mutations.**
  - The model filter reads `EmbeddingGenerator.model`.
  - The trace hook lives **inside** `QueryEngine.query`, not in a harness copy
    of its steps.
  - The breadcrumb test composes the retriever's own expression constant.
- **Ask what the fixture cannot distinguish.** In the vector-leg isolation test,
  the other tenant's vector is the **nearer** one.
- **Commit before mutating; prove each mutation landed.**
- **Measure before claiming.** The verdict comes from `compare_runs.py`'s exit
  code and output.
- **Environment facts:**
  - `testcontainers` needs the workers venv.
  - The gate makes real OpenAI calls. Check the key by its length only.
  - Never use port 5434.
