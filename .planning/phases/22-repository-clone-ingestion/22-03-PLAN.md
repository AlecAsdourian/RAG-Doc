<objective>
Move the vector leg of retrieval from Qdrant into Postgres and retire Qdrant.
After this plan:
- both legs run under one tenant scope;
- the vector leg uses iterative index scans, which the repository filter needs;
- a query is never compared with vectors from a different embedding model;
- nothing in the repository talks to Qdrant.

Then prove the move changed storage and nothing else. The three benchmark
corpora are measured on the same chunks and the same ada-002 vectors, read once
through Qdrant and once through pgvector, **under an equivalence rule written
in this plan before anything is measured.**

**Output:**
- the vector leg in SQL;
- the keyword leg without its latest-run filter;
- Qdrant removed from code, compose, dependencies and the harness;
- a committed comparison script;
- the equivalence result.

**Estimate:** 12–18 h, 3 tasks.
</objective>

**Locked decisions this plan implements:**
- **P5** (a correction to D2 §5): `hnsw.iterative_scan` is load-bearing.
- **P6** (U3 + U10): both legs in Postgres; fusion and boosts stay in Python;
  the move changes storage and nothing else.
- **P15** (D2 + U1): Qdrant leaves.
- **P4** (U3): `embedding_model` recorded; the model stays ada-002.
- **The `DECISIONS.md` correction it implements:** §5's repository filter
  (measured: without iterative scan, 16/20 and 20/20 queries came back short).

**P5's execution detail, decided here: `relaxed_order`, then re-sort the
returned rows by their exact distance in Python.**
- The pgvector README says relaxed ordering "allows results to be slightly out
  of order by distance". Recall measured the same under strict and relaxed.
- Re-sorting what came back restores exact order at no cost. A materialized CTE
  would do the same in SQL; choose it only if the Python re-sort proves awkward.

**Measured facts** (`22-RESEARCH.md` Q5).
- **The query vector must be a bound parameter.** A bound constant and an
  inlined CTE constant both used the HNSW index scan. A query vector drawn from
  a table through a subquery produced a sequential scan. psycopg2 interpolates
  parameters on the client, so `%s::vector` is the right shape.
- **At benchmark scale, pgvector does exact search.** A 3,000-row tenant got a
  sequential scan and a sort.
- **Qdrant may not have been exact.** Its collection config reads
  `full_scan_threshold: 10000` (kilobytes), and 5,400 × 6 KB is larger than that.
  The harness filters by `repository_id` with no payload index. So Qdrant may
  have searched approximately. **This is why the rule below compares each leg
  with exact search, rather than requiring identical ranks and nothing else.**
- **Duplicate-content chunks never had a Qdrant vector.** That was 12 in
  miniflux and 80 in mealie (the chunk counts minus the distinct hashes). 22-02
  gave them one in Postgres, so they can now enter the vector leg. That is an
  expected, explainable difference.

**The harness defaults to the compose databases.** `rag_quality_harness.py:123-124`
defaults to `DATABASE_URL = 127.0.0.1:5434` and `QDRANT_URL = localhost:6333`,
which are compose's ports.
- **This plan never uses compose.** Every run exports `DATABASE_URL` and
  `QDRANT_URL` pointing at scratch containers, and prints `host:port` (never
  credentials) before any `--ingest`.
- **Task 2 adds a guard:** `--ingest` and `--clear` refuse port 5434 unless
  `--allow-compose` is passed. Nothing in this plan passes it.
- **`--ingest` still refuses an indexed corpus without `--clear`** (ISS-027).

**Lessons from Phase 21 that apply here:**
- **A helper carrying its own copy of a predicate is blind to mutations of the
  original.**
  - The model filter must read the model from the **same** `EmbeddingGenerator`
    the writer uses (22-02). It must not hold a second
    `"text-embedding-ada-002"` literal.
  - The keyword-leg `EXPLAIN` test must use the retriever's own SQL constant,
    not a pasted copy.
- **Ask what the fixture cannot distinguish.** A vector-leg isolation test whose
  two tenants store the **same** vector cannot tell "filtered by tenant" from
  "returned the nearest". Give them different vectors, and put the other
  tenant's vector **nearer** to the query.
- **Commit before mutating; prove each mutation landed.**
- **Measure before claiming.** The equivalence verdict is recorded from the
  comparison script's output, not from reading the numbers by eye.
- **Environment facts:**
  - `testcontainers` needs the workers venv.
  - The backend is untouched here. If its suite is run as a check, point
    `DATABASE_TEST_URL` at a scratch pgvector container, never 5434, and expect
    the known CRLF-only failure of `TestSignatureComparisonIsConstantTime`.
  - The gate's ingest makes real OpenAI calls. Check the key is present by its
    length only; never print it.

**`VectorRetriever(postgres_conn, embedding_generator)`.** No Qdrant.
`search(query, organization_id, repository_id, limit=50)` does this:
1. Embed the query with `embedding_generator`: ada-002, unchanged (U3).
2. Inside `require_tenant(conn, organization_id)`:
   - `SET LOCAL hnsw.iterative_scan = relaxed_order`;
   - a module-level `VECTOR_SEARCH_SQL`:
     ```sql
     SELECT id::text AS chunk_id, file_path, breadcrumb, chunk_type,
            embedding <=> %(q)s::vector AS distance
     FROM chunks
     WHERE repository_id = %(repo)s AND embedding_model = %(model)s
     ORDER BY embedding <=> %(q)s::vector
     LIMIT %(limit)s
     ```
   - `%(model)s` is `embedding_generator.model` (P4). Never compare across
     models.
3. Re-sort the rows by `distance` (P5). Return
   `vector_score = 1 - distance`, the cosine similarity Qdrant used to report,
   so downstream fields keep their meaning.

**The rule, fixed here, before any measurement exists.**

*The storage move passes only if, for every question in every set (`tuning`,
`holdout`, `confirm`) of every corpus (`self`, `miniflux`, `mealie`), the final
file rank and the final symbol rank are equal under Qdrant and under pgvector,
or the difference is fully explained by one of:*
- *(a) a chunk that had no Qdrant vector (duplicate content) entering or leaving
  the vector leg's top 50;*
- *(b) the Qdrant vector leg differing from exact search where the pgvector leg
  matches exact search;*
- *(c) an RRF tie, meaning equal fused scores, ordered differently.*

*Any unexplained difference fails the gate. Then stop, record it, and
investigate. **Do not tune anything.** Aggregate MRR and top-5 counts are
reported, but they are not the criterion.*

This is an equivalence check, not a quality decision (U3, U10), so it needs no
fresh blind questions. Every question in every set is used, because none of
them decides anything here.

**Procedure. Scratch containers only, on free ports. Never compose.**
1. Start a fresh `pgvector/pgvector:pg16` and a scratch `qdrant/qdrant` on free
   ports. Export `DATABASE_URL` and `QDRANT_URL` pointing at them, and print
   `host:port` for each.
2. **Baseline code, which still reads Qdrant:** a `git worktree` at this plan's
   base commit, the 22-02 merge.
   - Apply migrations to the scratch database.
   - `--ingest` the three corpora. The corpora are already fetched at their
     pinned commits in `../rag-bench-corpora`; check with `--fetch --check`.
   - That ingest writes **each vector once and stores it in both places**,
     because the 22-02 pipeline writes Postgres and Qdrant from one embedding
     call.
   - Then `--measure --set all --json-out baseline-<corpus>.json`.
3. **This plan's code, which reads pgvector:** `--measure --set all --json-out
   pgvector-<corpus>.json` against **the same scratch database, with no
   re-ingest**. The chunks and vectors are therefore identical, and only the
   read path differs.
4. **The exact baseline for (b).** For each question, compute the exact cosine
   top 50 in SQL, as the app role under the tenant with `enable_indexscan` off,
   using the same query vector. The harness records query embeddings, or
   `compare_runs.py` re-embeds with ada-002 once and caches them.
5. `compare_runs.py baseline-*.json pgvector-*.json --exact …` lists every
   question whose file or symbol rank differs. It classifies each difference as
   (a), (b), (c) or **UNEXPLAINED**, and exits non-zero on any **UNEXPLAINED**.
6. Tear down both containers and the worktree.

**Cost:** one embedding of the three corpora, about $0.09 on ada-002 by
`22-RESEARCH.md`'s measured totals, plus about 130 query embeddings. It needs
`OPENAI_API_KEY`, which must never be printed.

**Record in `22-03-equivalence.md`:**
- the commands, with no secrets;
- the per-corpus table of differences and their classifications;
- the aggregate metrics under both;
- the verdict.

The rule above is **copied into that file verbatim, not paraphrased,** and is
committed with this plan, before step 1.
