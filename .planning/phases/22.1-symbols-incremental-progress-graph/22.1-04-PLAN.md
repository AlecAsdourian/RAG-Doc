<objective>
Build D3's tier 1: the graph edges the parser can see without running a
build, stored so that tier 2 (SCIP, uploaded from the customer's CI, later)
can upgrade them in place and never be downgraded by them (P9).

1. **`symbol_edges`**, created here (moved from 22-02), with D3's evidence
   lattice and partial unique indexes, and **D3's upgrade and no-downgrade
   rule tested first**, before any producer exists. Tenancy by composite
   keys from the start, so the table cannot repeat ISS-036.
2. **Candidates from the parse.** Call sites and imports, per language,
   from the same tree 22.1-01's walk reads, each attributed to its innermost
   enclosing symbol (a file's top-level code to its `module` symbol).
3. **The resolver** (imports plus scope matching) writes `calls` and
   `imports` edges with `to_symbol_name` always set: `partial` when bound to
   a symbol, `unknown` when not. It re-resolves across files on every
   ingest, so an incremental that changes a callee's file updates the
   unchanged callers' edges.
4. **A `CYCLE`-safe traversal helper**, tested on a cyclic fixture, every
   query excluding archived symbols.
5. **D1's third verification:** a re-export resolves to its leaf's id.

plus indexes on `(to_symbol_id)` (callers) and `(repository_id,
source_tier)`; RLS, FORCE, the scalar policy, `trg_assert_tenant`.
**Unpartitioned**, for P7's reason. The composite keys make an edge between
two repositories unrepresentable (SU17). Symbols are never deleted by
ingest, so the cascades fire only on a repository delete.

**The tier rules, as statements** (`workers/graph/edges.py`, one constant
each, all tested in Task 1 before any producer exists):
- `TIER1_DELETE_FOR_FILES`: delete the edges **whose `from_symbol_id`
  belongs to the given files** and `source_tier = 1`. Tier-2 rows are never
  deleted by tier 1.
- `TIER1_INSERT_RESOLVED`: D3's upsert, `ON CONFLICT (organization_id,
  from_symbol_id, to_symbol_id, edge_kind) WHERE to_symbol_id IS NOT NULL
  DO UPDATE SET evidence = EXCLUDED.evidence, source_tier =
  EXCLUDED.source_tier, updated_at = NOW() WHERE EXCLUDED.source_tier >
  symbol_edges.source_tier`, verbatim.
- `TIER1_INSERT_UNRESOLVED`: inserts only `WHERE NOT EXISTS (a row with the
  same organization_id, from_symbol_id and to_symbol_name and source_tier >
  1)`, the **phantom guard**; `ON CONFLICT … WHERE to_symbol_id IS NULL DO
  NOTHING`.
- `TIER2_RECONCILE`: D3's `DELETE`, **without `edge_kind`** (P9), then
  `TIER2_UPSERT`, in one transaction. No tier-2 producer exists (K3,
  later); these are the contract tier 2 must use, tested now.
- `RERESOLVE_SQL`: for the repository's tier-1 edges whose `to_symbol_key`
  names a **live** symbol (`file_path || E'\x1f' || symbol_path`, through
  `idx_symbols_live`), set `to_symbol_id` and `evidence = 'partial'`; for
  those whose `to_symbol_id` is now archived and no live symbol carries the
  key, keep the row (graph queries exclude archived targets). One
  statement per ingest, after the symbols are written.

**The candidates** (`workers/graph/candidates.py`, from the tree the
chunker parsed; no second parse):

| Language | Calls | Imports |
|---|---|---|
| Python | `call`: the function child's text (`f`, `self.m`, `mod.f`, `obj.m`) | `import_statement`, `import_from_statement` (relative levels kept), `Y = X` at module level (P8's alias) |
| Go | `call_expression`: `F`, `pkg.F`, `recv.M`; composite literals are not calls | `import_spec` (path, alias); `type A = B` (P8's alias) |
| TS/TSX/JS | `call_expression`, `new_expression` | `import_statement` (default, named, namespace), `export … from` and `export *` (re-exports), `export { X as Y }` |

Each candidate carries the from-symbol (the innermost enclosing symbol from
22.1-01's walk; top-level code is the `module`'s), the raw callee or
imported text (stored as `to_symbol_name`, the name tier 2 matches on, so
tier 1 **always** sets it, as D3 requires), and the line (not stored).
`require()` is a call to `require`, unresolved.

**The resolver** (`workers/graph/resolver.py`), pure Python over the
repository's live symbol table (read once per ingest: `file_path,
symbol_path, kind, ordinal, id`) and the candidates:
1. **Module resolution:** Python relative imports by directory; Python
   absolute imports by matching the dotted path to a repository directory
   or file (the shortest unambiguous match); Go import paths by the longest
   repository-directory suffix (`github.com/x/y/pkg/api` → `pkg/api/`),
   unambiguous or unresolved; TS relative specifiers with the usual
   extension and `index` probes. Path aliases (`@/…`) are unresolved
   (SU20).
2. **Names:** a bare name binds innermost first (a nested definition, the
   file's own symbols), then an imported name (following re-exports to the
   leaf, cycle-safe), else unresolved. `self.m` and `this.m` bind to a
   method of the enclosing class; `mod.f` and Go `pkg.F` to a symbol of the
   resolved module or package (a Go package is a directory, every file in
   it); Go `recv.M` binds when `recv` is the method's receiver. A class
   name called is a `calls` edge to the class. A method on an unknown
   receiver is unresolved.
3. **Several symbols at one `(file_path, symbol_path)`** (overloads, a
   property and its setter, a merged interface): one edge to each, all
   `partial` (SU19).
4. The output per candidate: `to_symbol_key` (`file_path \x1f symbol_path`)
   when a module and name resolved, even if no such symbol exists yet;
   `to_symbol_id` when a live symbol carries the key; `evidence =
   'partial'` when bound, `'unknown'` when not (D3's lattice; SU18).
5. **`resolve_name(repository_id, file_path, name) -> List[UUID]`**,
   following import and re-export edges to the leaf definition, used by D1's
   third verification and, later, by D4's anchoring by name.

**The store** (with 22.1-02's order, the job row's lock last): after the
symbols are upserted and archived, `TIER1_DELETE_FOR_FILES` over the parsed
and removed files, the inserts for the parsed files' candidates, then
`RERESOLVE_SQL` over the whole repository, so an unchanged file's edge into
a changed file follows the change. A full ingest is the same with every
file parsed.

**SU questions for the user** (continuing from 22.1-02's SU10–SU15):

**SU16 — Two changes to D3's transcribed DDL.** Recommended: **both.**
- (a) **composite keys** `(from_symbol_id, repository_id)` and
  `(to_symbol_id, repository_id)` into `symbols (id, repository_id)`, in
  place of D3's single-column keys: as written, D3's DDL repeats ISS-036
  (an edge could cite another tenant's symbol on its own row);
- (b) **a `to_symbol_key` column**, the resolver's qualified target, so an
  incremental re-resolves edges by one SQL join instead of re-parsing every
  file (the alternatives: re-parse every file on every push, which undoes
  22.1-02 for the graph; or a per-file import table re-run through the
  Python resolver, +3–4 h and a second table).
Both are additive to D3's contract with tier 2 (`to_symbol_name` stays the
join key, and tier 2 ignores `to_symbol_key`). 0 h beyond the estimate.

**SU17 — Edges across repositories.** Recommended: **none in tier 1**; the
composite keys forbid them. Tier 1 cannot resolve across repositories
anyway (it sees one tree). When tier 2 lands (K3), a cross-repository
reference stays an unresolved name until a later migration relaxes the key
for tier 2 only. The alternative, single-column keys now, reopens ISS-036.

**SU18 — The evidence a tier-1 edge carries.** Recommended: **`partial`
when bound to a symbol, `unknown` when not**, as D3 reads ("Tier 1 emits
'partial'"; an unresolved reference "is exactly what evidence='unknown' is
for"). Confirming, not choosing. 0 h.

**SU19 — A name with several symbols behind it.** Recommended: **an edge to
each, all `partial`** (tier 1 cannot tell an `@overload` stub from the
implementation that runs, or which accessor a call reaches). The
alternative, `ordinal 0` only, is wrong for overloads, where the
implementation is last. 0 h.

**SU20 — How far module resolution reaches.** Recommended: **what the
fetched tree shows**: Python and TS relative imports, Python absolute
imports by directory, Go import paths by directory suffix; TS path aliases
(`@/…`) and Go module paths from `go.mod` stay unresolved names, measured
per corpus by the census. The alternative is to fetch `go.mod`,
`tsconfig.json` and `package.json` as resolver inputs, never chunked or
embedded: it changes the fetch filters and the progress contract's
`unsupported` counts, +3–5 h, and is worth it if linkwarden's census shows
most of its imports are aliases.

**SU21 — A floor on the resolution rate.** Recommended: **record, do not
gate.** The census reports per corpus and per kind the share of candidates
bound; there is no rule yet that a number must meet, and writing one after
seeing the numbers would be the order the protocol forbids. If the user
wants a floor, it is committed before the census runs (+0.5 h).

**SU22 — 22.1-05's operating numbers and the store's new work.** The store
now writes symbols (22.1-01) and edges, from four to six candidates per
chunk on the measured corpora (Q7's counts against Q6's chunk counts:
mealie 12,284 over 2,816, miniflux 13,223 over 2,134), inside the
completion transaction, and 22.1-05's `max_job_duration` (N1) and
`stop_grace_period` (N6) are functions of the store time at the cap.
Recommended: **add "the store gains statements" to 22.1-05's re-measure
triggers, and re-run its at-cap store measurement after this plan** (free:
the replay embedder, no OpenAI; ~1–2 h, inside this plan's estimate if PR
