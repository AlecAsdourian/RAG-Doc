# Phase 22.1 Plan 03: the progress contract, `status`, and ISS-034's `current_job`

Phase 23 can now reach a repository's current job from the repository API
and tell what it is doing from one word computed on the job row. The
progress column is documented as built, and a test fails when the code and
the document disagree. ISS-034 is closed on shape 1.

## 1. The progress contract (Task 1, S5)

`docs/api-ingestion-jobs.md`, "Stages and progress" → **"The progress
contract"**, replacing the sentence that deferred it here. It states: what
`null` and `{}` mean; per attempt (replaced whole) and cumulative within an
attempt; **no ending writes it** (grep of `workers/jobs/transitions.py`:
neither `progress` nor `last_stage` appears in a statement; the only writer
is `PROGRESS_SQL` in `runtime.py`; `pkg/jobs` writes neither); the seven keys
with a **type** column and "first reported at"; **all 18 skip reasons** in a
new table, each with its meaning and the pass that counts it (extraction or
walk); what `progress` is not (not a percentage; per-slice embed reporting
recorded as an option for 23-03, not built; `chunks_stored` true of a
`completed` row only); and the stability rule.

22.2-02 had **not** merged when Task 1 ran (`RAG-Doc/main` at `ffdd06e`), so
the contract lists the keys on `main`; 22.2-02's `chunks_truncated` will be
asked for by the pin test when that plan adds it.

**The pin test**, `tests/ingest/test_progress_contract.py`, no database and
no network. It reads the doc's two tables between `<!-- progress-keys -->`
and `<!-- skip-reasons -->` markers (never the prose), and:
- runs the real handler through `test_handler._run` with `fakes.py`'s fakes
  over three fixtures: the happy path (whose tree carries a committed `.env`,
  so `skipped` holds `secret`), one file raising in the chunker, and the
  chunk cap. The union of reported keys equals the doc's keys, the stage at
  which each first appears equals the doc's column in every run, and every
  run's first report is `("fetch", {})`;
- checks the completed run's last report: every value an `int >= 0`, or for
  `skipped` a `str → int >= 0` dict, matching the doc's type column;
- collects every skip reason statically with `ast` over `archive.py` and
  `filters.py` (string subscripts of `skipped`, `Verdict(False, …)`'s second
  argument, `_member_kind`'s string returns). **Premise first:** the
  collector must find at least the 18 reasons read from the code; then the
  collected set equals the doc's.

`handler.py`'s docstring still points at the doc for the keys (checked,
unchanged). `jobs.go`'s stale `clone|parse|embed|store` sentence is replaced
by a pointer to the doc.

## 2. `status` (Task 2, S8)

On the job object, wherever it appears. Computed by one `CASE` in
`jobColumnsSQL`, against the database clock, in the order of the doc's table
(first match wins), ending in `ELSE j.state`:

| `status` | The row |
|---|---|
| `dead_pending` | `attempts >= max_attempts` and either `queued`, or `running` with a NULL or expired lease (**not** a live lease: a healthy final attempt is also at the cap) |
| `stalled` | `running`, lease NULL or expired |
| `running` | `running`, lease live |
| `deferred_suspended` | `queued`, installation `suspended_at` set and `uninstalled_at` NULL |
| `retrying` | `queued`, `attempts > 0` |
| `scheduled` | `queued`, `attempts = 0`, `run_after > NOW()` |
| `queued` | `queued`, `attempts = 0`, `run_after <= NOW()` |
| `completed`, `dead`, `superseded` | that state |

The authority, with what a UI says for each and the polling guidance for
23-03, is `docs/api-ingestion-jobs.md`'s status table. `jobByIDSQL` now
`LEFT JOIN`s `repositories` and `github_installations` (both under row-level
security in the tenant transaction) for `deferred_suspended`; its
`AND j.organization_id = $2` stays the whole guard.

## 3. ISS-034: `current_job` (Task 2, S6)

**Shape 1, as the user accepted it on 2026-10-06.** `Repository.CurrentJob
*IngestionJob \`json:"current_job"\`` — never `omitempty`. "Current" is
defined once, in `currentJobJoinSQL`: two lookups combined with `COALESCE`,
the live job first (`idx_ingestion_jobs_one_live_per_repo`), else the newest
by `(created_at DESC, id DESC)` (the new index), each filtered by
`organization_id = $1`; then a primary-key join to the chosen id.

- **`$1` is the organization in every statement.** `List` was renumbered
  (`$1` claim, `$2`/`$3` cursor, `$4` limit; semantics unchanged) and `Get`
  is `$1` claim, `$2` id. `List` and `Get` read `auth.OrgIDFromContext` and
  gained jobs.go's 403 guard, read first. `Connect` binds the `orgID` it
  already reads from `github_installations` under row-level security; no
  second claim read.
- **Scanning a missing job:** `jobScan` scans into nullable targets and
  `job()` returns `nil` when the id is NULL; `jobByIDSQL` uses the same
  struct, so the column-to-field mapping exists once.
- **`Connect`'s `201`** carries the job it enqueued, the live job it joined,
  or the latest, read in its transaction after the enqueue.

**Not chosen: shape 2**, a history list. It is additive later (~3–4 h, the
same isolation pattern) and nothing here blocks it.

## 9. Measured, inferred, and not pinned

**Measured:** every test result, mutation and proof above; the EXPLAIN; the
gate; up/down/up; the `25001` refusal.

**Inferred:** that golang-migrate's postgres driver sends a migration file as
one query string (its documented behaviour; the header's argument against
`CONCURRENTLY` rests on it, and on the measured refusal); that a planner on a
production-sized table chooses as it did at 19,900 rows.

**Does NOT pin:**
- **A job queued under an uninstalled installation reads `queued`,
  `scheduled` or `retrying`** (ISS-033's race) until a worker claims and
  abandons it. Documented; not computed.
- **`progress` has no mid-embed report.** A UI cannot show a share of the
  embedding done. Recorded as an option for 23-03.
- **There is no job history list** (shape 2). An older job's `last_error` is
  unreachable once a newer job exists.
- **The pin test sees only the keys its fixtures' paths report** (happy
  path, one file raising, the chunk cap): a key reported only on another
  path would slip through. And **only the reasons in `archive.py` and
  `filters.py`**: a reason minted in another module would not be collected.
- **`current_job` is `null` after Phase 24's 30-day pruning** for a
  repository untouched that long; documented, not tested (no pruning exists
  yet).
- **The live lookup's `LIMIT 1` has no `ORDER BY`**: correct only because the
  partial unique index allows one live job per repository.
- **The final join to `ingestion_jobs j` carries no organization filter**: it
  is by primary key on an id only the two filtered lookups can produce, and
  the filters' mutations are what pin that.

## 10. Deviations from the plan

1. **M8's form.** The plan's `AND true` changes `jobByIDSQL`'s arity; run as
   `(j.organization_id = $2 OR true)` instead (§6). Same intent, the
   checklist's rule.
2. **P1b added**, a fifth Python mutation (§6).
3. **The pin test's premise message** widened in a second commit (§6).
4. **The Scenario7 of the plan's test list is a process check**, not a Go
   test: no route was added, so there is nothing for a test to request; the
   scanner run is the evidence.
5. **`Get` and `List` 403 guards use distinct variable names**
   (`getOrgID`, `listOrgID`) so each mutation matches exactly once.
6. **The migration uses `CREATE INDEX IF NOT EXISTS`**, so an index an
   operator built concurrently by hand first is skipped rather than refused.
