**THE RULES. Task 1's first commit copies this section verbatim into
`22.1-05-operating-numbers.md` and `22.1-05-recall.md`, before any timing run
or recall query (S9).** Nothing measured afterwards edits a rule. If a rule
proves unworkable, the plan stops for that number: it records the
measurement, keeps the provisional value, and tells the user.

*Measured quantities* (every run as `rag_doc_app` on a scratch
`pgvector/pgvector:pg16`, 22-01's digest, started with
`shared_preload_libraries=pg_stat_statements`; the host recorded):
- **Stage times:** from the runtime's stage lines (`runtime.py:794-801`,
  one per report), the claim line and the completion line. Fetch's bytes come
  from its own line (`handler.py:450-461`).
- **Tokens and calls:** the API's `usage.total_tokens` per call, and the
  calls per embed stage.
- **Rate limits:** the `x-ratelimit-limit-tokens` and
  `x-ratelimit-limit-requests` response headers, names and numbers only.
- **Heartbeat cost:** `HEARTBEAT_SQL`'s `max_exec_time` from
  `pg_stat_statements`, plus every `57014` and every "assuming it is lost"
  line in the worker's log.
- **Memory:** peak RSS from `ru_maxrss`, measured in `python:3.11-slim`, the
  production image.
- **Disk:** peak working-directory bytes, sampled every 0.5 s.

*The rules:*

- **N1 — `max_job_duration`.** Let `T_cap` = `F_cap + P_cap + E_cap +
  S_cap`, where:
  - `F_cap` = 500 MB × the slowest measured seconds per MB of download, plus
    500 MB × the slowest measured seconds per MB of extraction and walk, over
    the four real repositories;
  - `P_cap` = the parse time measured at the cap (Task 2's synthetic run),
    the maximum over its runs;
  - `E_cap` = 100,000 × the highest measured tokens per chunk ÷ the lowest
    measured single-worker tokens per second;
  - `S_cap` = the store time measured at the cap **after** the A-L3 fix, the
    maximum over its runs.

  Then **`max_job_duration` = 3 × `T_cap`, rounded up to the next 15
  minutes**, and never less than 3 × the longest real job measured. The ×3
  is P16's own margin, kept. A result above 4 h is still applied, and the user
  is told, because a deterministic overrun costs five attempts (22-05 §16).
- **N2 — the lease (A-L3).** First, measure A-L3 on the code as it is, at the
  cap. Then fix it (Task 2) and measure again.
  - The lease **stays 5 minutes** if, after the fix, across every run at
    every size (single and concurrent):
    - no heartbeat is cancelled (`57014`);
    - no "assuming it is lost" line is logged;
    - `HEARTBEAT_SQL`'s `max_exec_time` is under 1 s.
  - Otherwise the lease = 2 × `S_cap`, rounded up to the minute, and the user
    is told the fix did not separate the store from the lease.
- **N3 — the heartbeat's `statement_timeout`.** Let `H` = `HEARTBEAT_SQL`'s
  largest `max_exec_time` over every run after the fix. The timeout = **the
  larger of 5 s** (`CONNECT_TIMEOUT_SECONDS`, `runtime.py:284`, so a beat's
  two waits share one scale) **and 10 × `H`, rounded up to the second**.
  - It must satisfy 240 s + timeout < the lease: four blocked beats still fit
    inside it, the reasoning of `runtime.py:327-333`.
  - If 10 × `H` exceeds 15 s, the database is the finding, not the number.
    Report it.
- **N4 — the pool size.**
  - Let `W_tpm` and `W_rpm` = the large repository's single-worker embed
    rate, in tokens per minute and calls per minute over its embed stage.
  - Let `TPM`, `RPM` = the key's limits from the headers.
  - `N_openai` = ⌊0.7 × min(`TPM`/`W_tpm`, `RPM`/`W_rpm`)⌋. The 30 % is left
    for query embeddings and bursts.
  - `N_db` = ⌊0.25 × `max_connections` / 2⌋, with the scratch server's
    `max_connections`; each worker holds two connections.
  - **`N` = max(1, min(`N_openai`, `N_db`)).**
  - **Confirmation:** `N` workers run concurrently, one corpus job each, with
    every job enqueued **before** any worker starts. If any "Rate limit hit"
    line appears (`openai_client.py:132-141`), or any job does not complete in
    one attempt, then `N` := `N` − 1 and run again, down to 1.
  - **Memory is recorded as a host constraint, not folded into `N`:** a host
    needs `N` × the peak RSS at the cap, plus headroom. Phase 24 picks the
    host.
- **N5 — the OpenAI throughput ceiling.** Record:
  - `TPM` and `RPM` as the key reported them, dated, naming the model;
  - `W_tpm` and `W_rpm`;
  - **the ceiling `C` = ⌊min(`TPM`/`W_tpm`, `RPM`/`W_rpm`)⌋ concurrent
    embedding workers.**

  No run provokes a `429` on purpose; that would spend tokens to learn what
  the headers already say.
- **N6 — compose's `stop_grace_period`.** A shutdown never interrupts a store:
  `write_results` has no checkpoint, so a worker that gets SIGTERM mid-store
  finishes the store first.
  - `stop_grace_period` = the larger of 2 min and `S_cap` + 30 s, rounded up
    to the minute.
  - Otherwise a store at the cap is SIGKILLed and rolled back on every
    shutdown.
- **N7 — memory and disk at the cap: findings, not settings.**
  - If peak RSS at the cap exceeds **4 GB**, file an issue carrying the
    measurement, proposing `float32` arrays and streaming the tree.
  - Replace the docs' "about 1 GB" disk figure with the measured peak.
  - **U6's caps are not changed.** They are the user's (U6 says they are
    "revisited after 22.1-05 measures"); the record reports what the
    measurements say about them.
- **R — the recall rule** (proposed here; **the user confirms or changes it
  at plan approval, before it is committed**). For each scope (a tenant, one
  repository, one query), comparing the production search with the exact
  baseline:
  - **R1** — the largest scope of the HNSW tenant is served by the HNSW
    index, under default planner settings and with iterative scan set as
    production sets it. `EXPLAIN` shows `Index Scan using
    chunks_pNN_embedding_idx`.
  - **R2** — the exact baseline's plan contains no `embedding_idx`.
  - **R3** — in every HNSW-served scope: mean recall@10 ≥ **0.95**, and every
    query's recall@10 ≥ **0.70**; mean recall@50 ≥ **0.90**. 50 is the
    production limit.
  - **R4** — in every exactly-served scope, recall@50 = **1.000**.
  - **R5** — **no short results** anywhere: every query returns min(50, the
    rows in its scope).
  - **R6** — no result belongs to another tenant or another repository.
  - **Recall is tie-aware.** A returned chunk counts as a hit if its exact
    distance is within **2e-6** of the exact k-th distance. 2e-6 is QD2's
    tolerance; mealie's duplicate-content chunks share vectors.
  - **If R1 fails**, no real repository up to the cap makes the planner choose
    HNSW. The record says so and the user is told: D2's "at production
    volumes the planner will use HNSW" is then unproven.
  - **If R3 fails,** nothing is tuned in this plan. The `hnsw.ef_search`
    curve (the default, then 80, 100, 200) is measured as exploration and
    brought to the user. Changing it changes rankings.

**Lessons from the checklist that apply here, at the point of use:**
- **Measure before claiming.** The rules come first; every number in the
  record names the run that produced it; inferred values are marked inferred.
  Commit before running any diff-based check.
- **Can this test fail?**
  - The recall test asserts its premises: the plan of each scope, the
    baseline's exactness, every co-tenant's placement in the shared partition
    read back through `tableoid`, and the row counts.
  - The mid-store heartbeat test must fail on the current code. Run it there
    first and record the failure.
- **A helper with its own copy of a predicate is blind.** The exact baseline
  runs the imported `VECTOR_SEARCH_SQL` with index scans switched off, never a
  hand-written query. The production search runs through `VectorRetriever`
  itself.
- **Isolation as a non-superuser.** Seeding and every query run as
  `rag_doc_app`. Probe `rolsuper` and `rolbypassrls` (both false) before the
  first query. Only migrations and grants run privileged.
- **Connection options merge, never replace.** Any measurement connection
  that adds an option goes through `_merged_options_dsn`.
- **Race tests race.** The concurrency run enqueues every job before releasing
  the workers.
- **Secrets.**
  - `OPENAI_API_KEY` is checked by its length only.
  - Only `x-ratelimit-*` header names and numbers are recorded.
  - The dummy token is a fixed non-secret string.
  - Never print `docker compose config`.
  - Captured logs are grepped for `sk-`, `ghs_` and `Authorization:` before
    they are committed.
- **Mutation checks:** commit first; use a `git archive` copy; prove each
  mutation by reading bytes; neuter rather than delete.
- **`finally` never holds an assertion.**
- **Process:** a scratch Postgres on a Docker-assigned port; **never 5434,
  never compose**. Scratch files go under `mktemp -d`, removed at the end, and
  `docker ps -a` is identical before and after. Run the Python suite in a fresh
  venv, as CI does, and again in `python:3.11-slim`.
