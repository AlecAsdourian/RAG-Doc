**P8 as this plan implements it (the user locks it, SU1).**

*Which definitions are symbols.* Identity follows the tree, not the chunk
list, so 22.2-04's chunk-shape changes cannot move an id (SU1(f)). A symbol
is minted for each of these, at any depth, and for nothing else:

| Language | Node | `kind` | `symbol_path` |
|---|---|---|---|
| all | the file | `module` | `''` (SU1(e)) |
| Python | `class_definition` | `class` | ancestor chain + name |
| Python | `function_definition` whose nearest named scope is a `class_definition` | `method` | chain + name |
| Python | any other `function_definition` (module level, nested) | `function` | chain + name |
| Go | `function_declaration` | `function` | name (chain, if nested in nothing) |
| Go | `method_declaration` | `method` | receiver type + name (`_go_receiver_type`) |
| Go | every `type_spec` (struct, interface, named, func, map, slice), grouped or not, at any depth | `type` (SU2) | chain + name |
| Go | each name of a package-level `const_spec`, grouped or not | `const` | name |
| TS/TSX/JS | `class_declaration`, `abstract_class_declaration` | `class` | chain + name |
| TS/TSX/JS | `function_declaration`, `generator_function_declaration`, a module-level `const`/`let` bound to an arrow function or function expression (the chunker's rule) | `function` | chain + name |
| TS/TSX/JS | `method_definition` inside a `class_body` | `method` | chain + name |
| TS/TSX | `interface_declaration`, `type_alias_declaration`, `enum_declaration` (QU4) | `type` | chain + name |

*Never minted (P8's alias rule):* Go `type A = B` (`alias_declaration`),
TypeScript `export { X as Y }` and `export … from`, Python `Y = X`, any
import. Also not minted (SU3): Go package `var`, Python module-level
constants, TypeScript non-function `const`, class fields and object-literal
methods. 22.1-04 turns aliases into `imports` edge candidates.

*`symbol_path`* is the full ancestor chain from the same
`build_ancestor_chain` the breadcrumb uses, joined by `.`, never truncated.
The breadcrumb's last four levels are therefore always a suffix of it, and
the breadcrumb itself is not touched. Names keep their source text, so a
TypeScript computed key reads `[Symbol.iterator]`; nothing parses a
`symbol_path` back by splitting it.

*`ordinal`*: the 0-based index among the file's symbols sharing
`(symbol_path, kind)`, in source order (D1). It separates the four measured
shapes: two Go `init()`, a Python property and its setter, `@typing.overload`
stubs (mealie: `UnitConverter.parse` ×3, `PlaceholderKeyword.parse_value`
×4, 22-RESEARCH Q6), and a TypeScript interface merged with itself. An
interface merged with a function differs by `kind`.

*The span.* `end_line` is the definition's last line. `start_line` is the
**earlier** of:
- the first decorator, by the chunk's rule (`_span_start_line`: Python's
  `decorated_definition`, TypeScript's three placements, a method's
  decorators past comments, `method_decorators`);
- the first line of the leading doc comment, by the docstring rule of its
  language (Go's comment run, `//go:` directives included because they sit
  in the run; TypeScript's JSDoc above the outermost node). A Python
  docstring is inside the body, so the span already holds it.

So a symbol's span starts at the same first decorator as its chunk unless a
doc comment sits above that decorator, in which case it starts at the
comment (SU1(c): QD6's "start at the same first decorator" and "include the
leading doc comment" both hold only in this reading). A `module` symbol
spans the whole file. A grouped Go type or const spans its own spec, plus
its own doc comment; the group's comment belongs to no symbol's span.

*`span_digest`*: SHA-256 hex over the UTF-8 bytes of the file's lines
`start_line..end_line`, as `content.splitlines()` yields them, joined by
`\n`. Line endings and a trailing newline therefore never move it; any other
byte in the span does, including a decorator or a doc comment (D4 decides
later what a comment-only change means; the digest makes either answer
possible, as P8 asks).

*The id*: `uuid5(NS_SYMBOL, repository_id \x1f file_path \x1f symbol_path
\x1f kind \x1f ordinal)`, as `000017:137-141` and D1 state, with `NS_SYMBOL`
a fixed constant in `workers/chunker/symbols.py`, derived once as
`uuid5(NAMESPACE_URL, "https://rag-doc.dev/ns/symbol/v1")` and pinned by a
golden-value test. Changing it, or the separator, re-identifies every symbol
in every repository; the test is what says so.
